# 故障处理 Runbook

面向管理员的异常处置入口。硬异常的定义与口径由 Feature #22 固化在 `/admin/ops`：只有零和/投影差异、成功调用无结算、结算无账本、C2C 数量或持有不一致属于硬异常；信用风险、失败率与争议只作为关注项呈现，系统不虚构阈值。

## 第一入口：/admin/ops

1. 查看顶部“账本已核对/账本异常”与“异常与关注”面板。
2. 硬异常按提示下钻：账本→账户与分录；调用→调用记录与结算；C2C→挂单与交易。
3. “巡检历史”确认异常是持续存在还是新出现（启动/周期/手动三种来源）。
4. “立即巡检”可在处置后立即复核，不必等周期任务。

## 常见情形

### 账本异常（零和或投影差异）

- 零和非零说明出现了未经约束路径的写入：保留数据库快照（先备份），记录最近一次巡检正常的时刻，检查该窗口内的管理调整与升级操作。
- 投影差异通常伴随具体账户：在账户详情中比对分录合计与投影，收集证据后由维护者判断是否需要账本调整（`POST /api/admin/ledger/adjustments`，必须填写原因并留下审计）。

### 成功调用无结算 / 结算无账本

- 属于结算链路硬异常。冻结新调用风险的最小动作是暂停对应渠道（管理员渠道治理页）。
- 用调用详情的尝试与快照定位卡住的调用；orphan 恢复任务会自动重试幂等终结，若持续失败保留调用 ID 与日志交给维护者。

### C2C 数量或持有不一致

- 数据库约束触发器理论上阻止此类状态；出现即代表约束被绕过或手工修改过数据。
- 保留现场，停止相关订单操作，将挂单与交易详情交维护者核对。

### 争议与受限账户遗留交易

- 争议在管理员“C2C 争议”页处理：放行给买家或退还卖家都必须填写原因；只能从 `disputed` 延长核实时间。
- 账户停用或信用冻结后，其既有持有仍可由对手方或管理员按 C2C 规则收尾，不需要临时重新启用账户。

## 升级与回滚

- 任何硬异常无法在 30 分钟内解释时：执行一次备份保留现场，回滚到上一个已知良好版本（部署 Runbook），再用恢复演练验证备份可用。
- 所有处置动作都会进入审计事件与巡检历史；处置完成后在 Issue 中记录脱敏时间线。
