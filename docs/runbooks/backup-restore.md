# 备份与恢复 Runbook

加密备份与隔离恢复演练流程。备份三要素必须分开保存：密文、备份口令、密钥环；任何两者合在一起都会让加密失去意义。

调用诊断中的原始客户端 IP 与位置、共享定位缓存及查询预算随全库备份保存，沿用本手册的加密与访问控制；关闭定位不会擦除既有备份中的数据。恢复演练应设置 `GEOIP_ENABLED=false`，避免演练产生新的外部 IP 查询。

## 执行备份

```bash
BACKUP_PASSPHRASE=<备份口令> \
DATABASE_URL='postgres://...@127.0.0.1:55432/oh_my_aihub?sslmode=disable' \
PGPASSWORD=<数据库口令> \
scripts/backup-database.sh backups
```

产出 `backups/backup-<UTC 时间>.dump.aes`（AES-256-CBC + PBKDF2）与同名 `.manifest.json`（密文 SHA-256、schema 版本、密钥环环境变量引用）。`backups/` 已被 `.gitignore` 排除，脚本也会拒绝写入未被忽略的目录。建议节奏：每日一次，重大变更（迁移、升级、大批账户操作）前后各一次。

## 恢复演练（必须定期执行）

```bash
BACKUP_PASSPHRASE=<备份口令> \
UPSTREAM_CREDENTIAL_KEYRING=<...> UPSTREAM_CREDENTIAL_ACTIVE_KEY_ID=<...> \
C2C_PRIVATE_DATA_KEYRING=<...> C2C_PRIVATE_DATA_ACTIVE_KEY_ID=<...> \
scripts/restore-drill.sh backups/backup-<时间>.dump.aes
```

演练在一次性隔离 PostgreSQL 容器中完成，不影响生产数据，步骤全部自动：

1. 校验清单 SHA-256 与密文一致。
2. 解密并恢复到隔离库。
3. 清除恢复出的全部旧会话（备份中的会话不得复活）。
4. 运行迁移到最新版本。
5. 以生产密钥环对隔离库启动后端，并核对账本：全部余额合计为 0、每个账户余额等于其分录之和。后端启动时逐条解密全部存量密文（未删除渠道的上游 Key、未删除的平台 API Key、全部 C2C 卖单的收款方式），密钥环缺少历史 key id 或密文损坏会使后端拒绝启动，演练在这一步失败；后端日志列出无法解密的记录类型、ID 与缺失的 key id（最多列出前 20 条并给出总数，不含明文或密文）；演练失败（后端启动失败、账本核对未通过等）时，脚本把后端日志末尾 50 行打印到 stderr，成功时不输出后端日志。暂无重加密工具，密钥环必须保留全部历史 key id，不得移除旧 key id。
6. 输出结论并清理容器。

任何一步失败都视为备份不可用，应立即重新备份并排查（最常见原因：密钥环轮换后旧备份缺 key、口令记错、密文传输损坏）。

## 真实恢复（灾难时）

1. 按“部署 Runbook”准备新环境与两组密钥环（必须与备份时一致或包含全部历史 key id，缺少时后端启动即失败）。
2. 用备份口令解密备份并 `pg_restore` 到新数据库，然后执行迁移。
3. `DELETE FROM sessions;` 清除旧会话，强制全部用户重新登录。
4. 启动后端；管理员确认 `/admin/points` 五项核对全部通过、关键计数与预期一致。
5. 恢复后第一份新备份立即执行，作为新恢复点。

## 市场切换的只读保全核验

`cutover-check` 只读取数据库，不执行迁移、清理、部署或授权切换。它使用独立的 `AIHUB_CUTOVER_DATABASE_URL`，不回退到普通服务的 `DATABASE_URL`。应先在隔离演练副本运行；真实实例切换环境和时点由维护者另行决定。

维护窗口中停止新的业务写入，让旧版本自然完成普通调用及后台 Responses，再停止旧服务。存在任一种未结束任务时，工具拒绝生成完整基线；不能通过直接改调用状态或删后台任务绕过排空。保全比较期间持续停止推理、用户管理和 C2C 等写入，否则真实新交易也会被正确识别为差异。

```bash
# 使用环境配置注入专用数据库连接，避免将凭据写进命令历史。
cutover-check --out /secure-evidence/market-before.json
# 将打印的 SHA-256 独立保留，不能在核验时从可能已被改动的文件重新生成。
cutover-check --baseline /secure-evidence/market-before.json --sha256 <先前保存的摘要>
```

源码环境可用 `go -C backend run ./cmd/cutover-check` 执行同一命令。基线文件以 0600 权限独占创建，重试不能覆盖；文件只包含表/列范围、行数、摘要、迁移版本、触发器定义摘要和核对违反数量，不包含记录正文、账户 ID、余额明细、密文或密钥。全表读取采用一个只读一致性事务、一个数据库连接和逐行哈希，不进入普通网关路径；运行时可能增加数据库读取负载，应在上述静止窗口执行，可用信号取消。

工具保护全部已存在业务表，仅排除明确授权退役的旧模型/价格/供应商配置及旧渠道选择。共享 `channels` 的历史 ID、所有者、名称、密文字节/AAD 所需身份与创建时间仍保留；新分组渠道及其选择另行完整保护。逐账户摘要和八项账本/C2C 核对能发现总余额不变的账户转移；三个账本触发器的启用状态、两个函数定义，以及既有受保护表的主键、外键和唯一约束也受保护；只豁免授权退役配置的引用，历史调用到账本/渠道、分录到账户的关联不能丢失。核验以原基线的列和范围重新读取，新增列不会掩盖旧内容，新增表不代替旧表保全。

完整输出 `matches:true` 仅说明该次静止窗口的受保护数据与机制一致，不证明真实上游功能、密钥环解密、部署兼容或生产切换已验收。差异、缺表/列、未完成任务、禁用触发器或核对失败均非零退出；保持入口关闭，排查并按编号迁移前向修复。切换后产生新账目时，不得恢复旧整库备份覆盖新交易。单独运行此核验工具不执行迁移。

### 编号迁移 0026 的执行边界

0026 删除旧供应商/地址、全局模型/价格档和旧渠道模型配置，移除渠道的旧连接设置及旧渠道选择。共享渠道行只标为业务删除，保留原 ID、所有者、名称、创建时间和密文；已存在的分组渠道、用户、Key/限制/别名、路由偏好与历史账目不做迁入或重写。降级明确拒绝，不能让旧镜像连接清理后的结构。

普通 `migrate` 会在应用任何待执行迁移前检查排空状态；有未结束普通调用或后台响应时拒绝并保留迁移版本。发现非空旧配置时也先拒绝。维护者明确选定切换环境、旧服务已停止且保全基线留存后，才在该环境的 `DATABASE_URL` 上执行 `migrate --allow-legacy-config-cleanup`；源码等价命令为 `go -C backend run ./cmd/migrate --allow-legacy-config-cleanup`。这个参数仅允许已约定的旧配置清理，不授权改账或清库，也不能绕过排空。不要将它加入日常 Compose/自动部署命令。

SQL 迁移会锁定相关表并再次核验排空和显式授权，事务失败不产生部分清理或 0026 版本记录；排查后可重试。同一数据库完成后普通迁移可重复执行。迁移后先复核原只读基线、密钥环启动检查与新目录服务，再开放写入；实际部署脚本必须先完成破坏性结构的回滚保护，相关源码位于独立运维仓库。本仓库的迁移和文档不能代替该保护，也不构成生产切换批准。
