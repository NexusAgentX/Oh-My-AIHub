# 典型费用

管理后台「典型费用」查看模型站内、分组模型、渠道模型三层估算，并调整窗口、分组样本阈值、更新周期与代表 token/请求/图片数量。`/api/typical-costs` 只提供聚合结果；消费者、平台 Key、调用列表和收入不在此接口中。估算不参与实际结算，账本净支付为零的自用调用仍使用它的可靠用量事实。

## 公式与来源

文本以配置的 token 数、图片以配置的成功产物数为主要比较单位，另显示配置的请求次数估算。只有已完成且全部费用分量有可靠计量的业务调用进入画像；探针、失败、缺计量与重复观察不计样。保留互斥 token、缓存 TTL 价档、四模态、实际 service tier、原调用时段/上下文档、图片和调用内工具单位，再按当前分组报价逐个重算；不平均百分比、单次单价或倍率。

分组当前报价样本达到阈值时使用本组结构；报价或相关子模型报价改变后，旧版本不计入本组当前样本，样本不足使用站内同模型结构并标明推算。分组渠道共享画像，渠道费用 = 分组费用 × 当前折扣，手续费另列。站内模型费用按本站有效分组业务样本加权，先合计费用与实际工作量再归一化；这里的站内不是互联网上所有供应商。

例如比较单位为 100 万 tokens：A 组一条调用为输入 90、输出 10、缓存读 0，基准价分别为 2、4、0.2，典型费是 2.2 积分。B 组输入 10、输出 10、缓存读 80，报价为 1、2、0.1，典型费是 0.38；B 的原厂参考分母用 B 的同一结构按 A 报价计算为 0.76，倍率 0.5。B 渠道折扣 0.4 时费用为 0.152，倍率 0.2。不能把 A 的缓存结构代入 B 的参考分母。

按请求与按 token 报价只在样本同时提供可靠请求/token 关系时换算；缺 token↔请求或成功产物关系，主要比较费用显示未知，独立请求次数估算仍可有值。原厂参考必须是该模型唯一有效参考源，缺参考或分母为零时倍率未知；工具/模态等分量缺报价也不当作免费。估算在 nano 精度汇总、归一化后向上取整，实际账单继续按每次冻结报价原子结算。

## 更新、版本与饱和

更新器只有一个 worker 和一个合并唤醒槽；同一周期内价格输入未变化的自动通知不重复扫描，手动更新仍可立即读取新调用。管理员「立即更新」入队，不在 HTTP 请求中扫描历史。配置用版本号避免覆盖他人的修改。每次计算固定样本水位、当前报价/折扣、参考源、汇率、手续费及参数版本，发布前复核；不回算或改写历史账单。报价版本、汇率或折扣不匹配的内存费用索引返回未知，不能作为零费用排序。

调用按 `(completed_at,id)` 索引增量读取，样本与 checkpoint 一起提交，用调用主键去重；每天滚动补扫当前窗口，修复在增量水位之后才提交的迟到账单。重启恢复 checkpoint 和仍匹配当前输入的快照。窗口扩大触发补扫，旧窗口样本只删除派生数据，原始调用/账本保留。

预算：两条私有数据库连接，每次 SQL/事务至多 5 秒；单次更新至多 30 秒，每次至多读取 4 页源调用、每页 250 条，补扫跨后续更新继续；清理每次至多 4×250 条。派生样本最多 20,000 条、单条 64 KiB，计算保留的编码样本最多 32 MiB；报价对象最多 4,096 个、渠道模型最多 20,000 个、重定价至多 100,000 次，快照最多 8 MiB。编码大小上限不等于进程 RSS，解析/工作结构还有有界额外开销。

超过预算、数据库故障、取消或输入变更不发布部分结果，保留上次快照和更新时间，显示更新失败或饱和；容量满可缩短窗口，清理释放空间后恢复。队列满的重复手动请求返回明确原因。转发只读取原子内存索引，无新增统计 SQL、队列等待或账本持锁工作。

开发不运行端到端性能 A/B。发版前按 [网关性能基线](gateway-baseline.md) 集中覆盖费用索引读取、更新器饱和与转发/结算并行；相关快速分配回归和微基准由开发验证。此功能不授权部署、生产清理或重新计算余额。
