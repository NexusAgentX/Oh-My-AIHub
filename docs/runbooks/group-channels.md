# 分组渠道运维

适用于 Epic #487 的分组渠道。生产切换与旧配置清理按最终切换 runbook 执行；代码合并不构成生产数据操作授权。

## 创建与配置

在「分组渠道」选择已批准分组并填写上游 Key。创建自动选择当前第一个地址和分组模型；渠道主可调整地址集合/顺序、逐模型排除与折扣。模型选择按提交项更新；明确提交空模型选择列表才重置，换组会清除原组选择并要求新 Key。未提交的选择不被另一模型编辑或迟到探针删除。

高级设置空值跟随当前分组默认值，填写则覆盖；请求头可选择继承整个块、明确空规则或自定义块。管理详情同时展示已保存继承来源。分组发布、渠道配置和治理操作成功前完成快照刷新；失败显示未就绪时先处理服务/数据库错误，不手工 SQL 绕过屏障。重建恢复后使用已提交配置，不能回退到旧全局模型价。重复保存须以最新修订号提交，冲突时保留本地草稿供检查。

地址被移除时只忘记对应稳定关系 ID。新增/恢复地址不会自动加入原选择；没有剩余所选地址时重新勾选后保存。分组业务删除会级联渠道，保留账本、账户、余额及历史引用；不因此清理上游文件、容器或未知资源。

## Key 探针

探针直接使用渠道主填写的 Key 调用上游，不写站内推理账本，实际费用由上游计算。文本模型验证四种原生基本调用；图片模型验证 Images、Responses、GenerateContent 的原生图片调用。每种协议独立保存状态，不把目录错误或一个协议失败当成所有模型不支持。文本请求至多 30 秒，图片至多 180 秒，响应至多 32 MiB；同组已选入口沿既定错误边界回退。没有通用 Files/工具资源 CRUD。

必要请求条件、模型能力摘要、Key 版本或主动重探序号变化后重新探测；价格、折扣和地址顺序不使结果过期。没有自然年龄到期策略。换 Key 后旧结果立即不再使用，迟到写入再次校验绑定；排除模型不被自动恢复。失败结果是终态，修复上游后使用「重新探测已保存 Key」；有未保存修改时先保存。队列满时保持待探测状态，由周期重扫补齐；不会启动无界工作或读取其他渠道/宿主凭据。

最小探针只证明本 Key 在当前协议入口的基本可调用性；目录与路由不再有“能力”维度，也不读取高级能力报告。无模型辅助请求的具体入口由 F7/F8 接入基础选择器，有明确授权模型上下文时使用它，否则手动模式要求适用的已保存顺序，自动模式按稳定渠道 ID 回退，不借其他模型的价格或速度。

## 诊断和后台调用

渠道详情包含概览、模型与配置、调用记录、健康事件。每次尝试显示稳定地址 ID 与同渠道/跨渠道回退层级；地址不会成为模型聚合维度。健康成功率每次渠道选取只计一次，中间地址错误保留诊断；历史没有新标识时沿用原有单次计数。

后台 Responses 以登记时的渠道、凭据、报价、配置及地址序列跟踪和结算。正在处理的任务不会因换 Key、停用或删分组而改用新凭据。新用户资源操作仍重新核验当前平台 Key；这与已登记工作的收尾不同。后台快照登记失败会执行已有取消收尾，禁止手工把任务标为结算完成。

## 开发与发版验证

相关快速 Go/前端测试与 lint 在本地执行；PostgreSQL、迁移升级、`-race` 与镜像交 CI。合成浏览器夹具仅供界面/机制验收，不是供应商支持证据。真实上游只使用明确提供的测试 Key 与其消费限制，禁止借用已有业务 Key 或宿主登录。

本轮开发、PR 和最终开发收尾不运行端到端性能 A/B。发版前统一按 [gateway-baseline](gateway-baseline.md) 比较最终集成候选：覆盖分组快照重建/发布屏障、候选与报价查找、A1→A2→B1 回退、原有并发/RPM/总调用预算、流式观察、同步结算，以及两个后台探针工作者与发布重建并发的场景。开发阶段保留 SQL 读取次数、分配/锁快速回归与微基准证据，A/B 待发版前执行。
