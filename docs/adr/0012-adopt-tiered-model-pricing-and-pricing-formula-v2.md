# ADR-0012：采用模型层多档价格与计价公式 v2

- 状态：已通过
- 日期：2026-09-03
- 决策者：仓库维护者
- 关联内容：[Epic #68](https://github.com/NexusAgentX/Oh-My-AIHub/issues/68)、[ADR-0008](0008-adopt-immutable-ledger-holds-and-pricing-formula-v1.md)、[ADR-0010](0010-adopt-snapshot-gateway-and-idempotent-settlement.md)

## 背景

上游厂商已出现两类超出「每模型一组四价」的真实计费模式：峰谷分时价（DeepSeek V4：北京时间工作日高峰时段全价，其余半价，折扣作用于含缓存的全部计费项）和按上下文长度阶梯价（Gemini 2.5 Pro ≤200k / >200k 两档；阿里百炼按单次请求输入 Token 总量分档）。行业口径已核实一致：档位按单次请求输入侧 token 规模判定，命中后整单（含输出与缓存价）按该档结算，不存在分段累进先例；分时价按请求发生时刻判定。现有 `models` 四价列与计价公式 v1 无法表达这两类价格，渠道利润随时段与档位被动波动。

人类产品负责人已于 2026-09-03 确认三项约束：本期谓词只做「输入长度 + 时间窗」两类；组合语义为多谓词 AND 命中、允许多条规则、首个命中生效、无谓词默认档兜底；档位定义在模型层（目录基准价），渠道层维持单一倍率作用于选档后四价。

## 决策目标

- 管理员可以为模型配置条件档位，覆盖峰谷与上下文阶梯两类上游价格，且可组合。
- 结算保持 ADR-0008 的任意精度与取整语义；无档位模型的计价结果与公式 v1 逐 nano 一致。
- 调用开始时的价格快照（ADR-0010）扩展到全部条件档，调用期间改价不影响在途调用。
- 预授权上界在任意档位最坏情况下仍是真实上界。
- 历史调用可解释：每笔成功调用记录命中的档位。

不解决：service_tier 等第三类谓词、分段累进计费、渠道级按档倍率覆写、表达式定价 DSL、自动抓取官方价格。

## 候选方案

### 方案一：倍率叠加（基准价 × 时段折扣 × 长上下文加价）

实现最小，但无法表达各档独立的四价（Gemini 长档输入 2 倍、输出 1.5 倍；智谱各档间无统一倍率），复合叠加后的最终价格不透明、难以对账。

### 方案二：结构化档位规则（条件谓词 + 各档独立四价）

`model_price_tiers` 每行为一组谓词（prompt token 半开区间 [min, max)、周几集合、带 IANA 时区的每日时间窗，支持跨午夜）加独立四价；多谓词 AND 匹配、按序首个命中、默认档兜底。OpenRouter 的 `overrides` 条件结构与 new-api 的实践均属此类（后者用表达式实现同类语义）。表达力覆盖全部已核实厂商案例，谓词种类可增量扩展。

### 方案三：表达式 DSL

表达力最强（new-api 路线），但引入解释器、校验与安全面，与本项目「任意精度、可快照、可对账」的零和账本架构相性差，审计困难。

## 决定

采用方案二。

- 档位存于模型层：`models` 四列保持为无条件默认档；`model_price_tiers`（seq 1..16）存条件档，每档四价沿用 0～100000 积分/百万 token 上限与九位小数。
- 选档口径：以「prompt 侧总量 = 输入 + 缓存写 + 缓存读 tokens」判定 token 谓词（三种协议适配器归一后口径一致，避免高缓存命中长请求误判短档）；时间谓词以 `api_calls.created_at`（请求开始时刻）在档位时区下的周几与日内分钟判定，区间为 [start, end)，start > end 表示跨午夜且窗口归属起始日；weekdays 与时间窗为两个独立子谓词。
- 整单按档：命中档位的四价作用于该请求全部四类 token；无命中回退默认档。
- 计价公式 v2（`ledger.CalculatePriceV2`）：先按上述口径选档，再复用 v1 的加权和与分别向上取整内核。无档位时数值与 v1 完全一致。`api_calls.formula_version` 放行 `formula-v1|formula-v2`，新调用一律写 v2；存量 v1 在途调用按原路径结算，不改写历史（延续 ADR-0008 的版本化要求）。
- 快照：`BeginCall` 在 `api_call_candidates`（默认档四价 + 倍率）之外，把全部条件档写入调用级 `api_call_price_tiers` 不可变快照；`FinalizeCall` 只读快照选档结算，并记录 `settled_price_tier_seq`（0=默认档）。
- 预授权：`ConservativeNetDebitUpperBound` 对默认档与全部条件档分别计算最坏上界并取最大。
- 渠道倍率语义不变：单一倍率作用于选档后的四价；未来渠道间上游成本结构不一致时，可在渠道层增加按档覆写倍率的扩展，本期不做。

## 后果

### 正面影响

- 平台可如实镜像上游峰谷/阶梯价，渠道利润不再随时段与档位被动波动；消费者价格透明可解释。
- 调用级档位快照使命中档位可审计、可复算，账单争议有据可查。
- 谓词结构可增量扩展（如未来 service_tier），不需要再次更换价格模型。

### 负面影响与成本

- 管理端每个多档模型需维护 4×N 个价格数字，价目维护工作量上升（产品负责人已确认接受）。
- 每次调用多一张快照表写入与一次档位装载查询。

### 风险与缓解措施

- 结算路径属于最高风险区：v2 为纯函数并以内置时区数据判定时间窗，配真实价目（DeepSeek 峰谷、Gemini 200k）单测；端到端集成测试覆盖快照隔离（调用中改价不影响在途结算）与选档记录。
- 时间窗语义错误（跨午夜、周几归属）会导致错档计费：匹配函数单测覆盖跨午夜归属起始日、边界开闭与周末场景。

## 验证方式

- `go -C backend test ./internal/ledger ./internal/catalog ./internal/gateway`：选档纯函数、真实价目样例、上界全档覆盖。
- `TEST_DATABASE_URL=... go -C backend test ./internal/postgres -run TieredPricing`：迁移 0007、BeginCall 快照、改价后快照隔离结算、命中档位记录的端到端验证。
- 生产部署后抽样成功调用，核对 `settled_price_tier_seq` 与账单金额可按快照复算。

## 替代关系

无；本 ADR 扩展而非取代 ADR-0008（计价公式 v1 对存量调用继续有效）。
