# ADR-0031：同步 Bifrost 目录并保留本地控制权

- 状态：已接受
- 日期：2026-10-08
- 决策者：维护者与 Agent
- 关联内容：#199、#200、#201；ADR-0012、ADR-0030

## 背景

管理员需要自动维护数千模型的价格和资料。Bifrost datasheet 提供模型资料与美元价格，但包含当前网关不支持的产品、缺价、条件价格和第三方托管版本，不能直接替换本地模型表。

## 决策目标

自动发现聊天和 Responses 模型；单模型可退出同步；明确来源、缺口和实际生效汇率。保持四种原生调用格式，不增加图片、语音、Batch 或工具附加费计量。

## 候选方案

### 方案一：按名称覆盖全部模型

实现简单，但会覆盖手工定价、混淆不同提供方，删除的模型也会复活。

### 方案二：独立来源身份和显式同步所有权

保留外部完整键与原始资料，本地模型只投影可靠字段；支持退出与删除墓碑。增加来源状态持久化，但可以隔离不完整数据。

## 决定

采用方案二。`model_sources` 独立保存完整键、原始 JSON、来源摘要、同步开关、状态、最后发现/应用时间与应用汇率；删除保留忽略记录。合法源键尽量保持，其他键使用可读清理前缀加源键 SHA-256 摘要生成合法稳定 ID，不按 basename 合并。手工模型冲突不接管，保留冲突记录。

源管理显示名称、价格和能力；启停、排序和备注由本地管理。默认新增停用。关闭同步后允许手工编辑，恢复同步后下一轮覆盖源字段。管理员写入与同步通过同一模型事务锁串行化。上游缺行仅标记 missing；下载或整体校验失败不更新任何模型。

美元到积分使用后台明确配置的固定换算率，初始为空。精确十进制有理数运算把 USD/token 转为纳积分/百万 token，在持久化边界向上取整一次。未配置或缺少有效基础价的新模型只有资料，禁止启用；已有有效价遇到不能解释的新资料时保留最后有效价及其应用汇率，并标记需人工处理。源资料缺失的能力在来源区显示未提供；最大输入与最大输出单独显示，不把含义不定的 `max_tokens` 当上下文。

可映射基础/缓存 TTL/模态 token 价、明确输入阈值、openai/anthropic/gemini 的明确服务档与独立 UTC 峰谷时间窗。缓存价缺失按 Bifrost 的规则回退对应输入价（[官方实现](https://github.com/maximhq/bifrost/blob/main/framework/modelcatalog/datasheet/cost.go)）；显式零保留。无法确认服务档与阈值交叉、嵌套 tiered_pricing/reasoning、fast/balanced/ultrafast、区域加价或冲突峰谷定义均需人工处理。Batch 和非 token/工具附加费仅提示未覆盖，不阻止可靠基础 token 价导入。

后台启动异步抓取，此后每 24 小时执行；管理员可手动触发。URL 固定、禁用重定向、有超时与响应大小限制、拒绝截断/空/重复键数据。数据库锁避免多实例重入，抓取期间换算率改变则拒绝应用旧换算结果。审计使用系统 actor，模型无变更不重复写修改事件。

## 后果

### 正面影响

- 自动维护模型资料，同时保留手工价格和运营控制。
- 原始来源与实际生效价格可追溯，删除与退出同步不被后台任务撤销。

### 负面影响与成本

- 部分复杂价格需手工处理；来源资料不是厂商准确性保证。
- 完整同步是一个事务，批次内可能短暂等待管理员编辑；管理页采用搜索与分页控制渲染量。

### 风险与缓解措施

- 来源缺价不视为免费；新模型停用、未就绪禁止启用。
- 来源键不等于渠道实际模型名；渠道仍明确配置上游名称与协议，不由资料推断可调用性。
- 来源失效保留最后有效价格并提示，不自动删模型或修改启停。

## 验证方式

精确转换、显式零/缺失、阈值边界、服务条件、峰谷冲突单测；真实资料全表解析；数据库覆盖幂等、手工冲突、退出/恢复、删除、不完整资料、失败、换算率变化与在途编辑；真实管理界面验收。

## 替代关系

无。
