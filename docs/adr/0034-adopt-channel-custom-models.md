# ADR-0034：渠道自定义模型与转为官方后待设倍率

- 状态：已通过
- 日期：2026-10-11
- 关联内容：[#325](https://github.com/NexusAgentX/Oh-My-AIHub/issues/325)、ADR-0012、ADR-0027

## 背景

渠道原本只能提供模型目录里的模型，`channel_models.model_id` 外键指向 `models(id)`，计价一律是「目录价 × 渠道倍率」。目录还没收录的新模型无法共享。我们希望渠道主能直接上架这类模型并自行定价。之后管理员会收录同名官方模型，此时原来的自定价格不再适用，需要渠道主重新按目录价设置倍率。

## 候选方案

- **自定义模型的存储**：
  - 另建一张 `channel_custom_models` 表。网关候选、在线列表和渠道读写都要合并两张表。
  - 复用 `channel_models`，加上 `is_custom` 和四个自定义价格列。去掉 `model_id` 的外键，官方行的完整性另行保证（用触发器，或用生成列外键）。
- **同名自定义模型**：
  - 按名称聚合：请求 `model` 时在所有同名渠道间路由。
  - 按渠道隔离：需要新的命名规则，客户端不再能只写模型名。
- **收录为官方模型时如何处理**：
  - 下架整个渠道。
  - 只停用该模型，并标记为待设倍率。

## 决定

- **存储**：复用 `channel_models`。
  - `is_custom` 为真时，四个 `custom_*_price_nano_per_million` 必填，倍率固定为 1，不开汇率优惠，也不能处于待设倍率状态；为假时四个价格必须为空。这些都由 CHECK 约束保证。
  - 生成列 `catalog_model_id` 只在官方行上等于 `model_id`，并引用 `models(id)`。这样官方行和待设倍率行仍受外键保护，删除仍被引用的模型照常失败，不需要触发器。
  - `route_prefs.model_id` 不再设外键，路由偏好按模型名保存。
- **计价**：自定义模型按渠道自填的积分价直接计费，不乘倍率、不乘汇率，也没有条件价格档。价格快照记录 `custom: true`。
- **按名称聚合**：同名自定义模型的渠道一起参与路由、冷却和回退。
  - 便宜优先：官方模型各渠道基准价相同，所以只比较倍率 × 汇率。自定义模型的价格各不相同，改按 3:1 混合价 `(3 × 输入 + 输出) ÷ 4` 排序，缓存价不计入。
  - 模型目录的最低参考价按同一口径选择渠道。
  - 由于自定义模型不能与目录模型同名，同一模型名的候选要么全是官方行、要么全是自定义行，两种口径不会混用。
- **名称互斥**：自定义模型名不能与目录中任何模型重名，包括已停用的模型。
  - 渠道保存时和 `catalogpg.CreateModel` 用同一把 `pg_advisory_xact_lock('model_name:' || 名称)`，渠道保存时还会在事务内再查一次目录。
  - 并发创建同名官方模型和同名自定义模型时，因此只会有一方成功。
- **转为官方**：`CreateModel` 在同一事务内把同名自定义行改成官方行：清空自定义价格，倍率重置为 1，`enabled = false`，`pending_multiplier = true`。同时为每个渠道写入 `model_pending_multiplier` 事件，并在 `model.created` 审计里记下受影响的渠道。
  - 渠道的其他模型不受影响。
  - 渠道主在保存时把该行设为启用，即视为确认倍率，待设倍率随之清除；只保存而不启用，仍保持待设倍率。

## 后果

- **收益**：
  - 新模型无需等管理员收录即可共享。
  - 收录后不会悄悄按旧的自定价格或默认倍率继续卖。
  - 官方行的外键完整性保持不变。
- **成本**：
  - 网关遇到目录外的模型名时，会多查一次是否有在线的自定义模型。
  - 3:1 混合价对输出占比高的请求不一定选中真正最便宜的渠道。
  - 自定义模型只有名称和价格，没有上下文、能力等展示信息。
- **风险**：
  - 自定义模型名由用户填写，不能作为指标标签，仍按目录过滤，统一归入 `other`。
  - 自定义价格不受管理员审核，渠道主对自己的定价负责，消费者通过模型详情查看各渠道的价格。
- **验证**：PostgreSQL 集成测试覆盖以下行为：按自定价格计费、按混合价选择渠道、收录后待设倍率并停止路由、删除模型被拒、启用后按目录价 × 倍率计费。
