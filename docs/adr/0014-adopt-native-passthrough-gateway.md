# ADR-0014：网关采用原生协议透传，计费约束仅在结算层执行

- 状态：已通过
- 日期：2026-09-04
- 决策者：仓库维护者
- 关联内容：[ADR-0010](0010-adopt-snapshot-gateway-and-idempotent-settlement.md)、[ADR-0008](0008-adopt-immutable-ledger-holds-and-pricing-formula-v1.md)、[Feature #87](https://github.com/NexusAgentX/Oh-My-AIHub/issues/87)

## 背景

ADR-0010 把网关定位为“只做同协议模型别名重写与元数据还原，不做格式转换”的原生协议代理。Feature #20 的实现额外引入了请求与响应的封闭字段白名单（`validateV1BillableRequest` 与响应/SSE 形状校验），以“最坏成本无法被四类 token 价格快照框住”为由，在入口拒绝 `previous_response_id`、`store`、`n != 1`、多候选、多模态、服务端工具、`anthropic-beta` 等原生字段，并把携带未知事件或字段的上游 200 判为失败。

这与产品合同冲突，也没有计费依据：预授权上界由目录 `2 × context_window` 与四类单价最坏组合计算，完全不读取这些字段；Hub 也不持久化响应正文或会话状态，`previous_response_id`/`store` 只是上游的会话指针与存储开关。实测后果是真实客户端的原生用法（Responses 流式、会话续接、chat 协议外的原生字段）被网关误拦，表现为 400 `unsupported_billing_shape` 或 502“所有候选渠道均失败”。

## 决策目标

- 网关回到透明转发：上游支持什么，平台就转发什么；协议理解范围收缩到路由与结算必需的最小集合。
- 计费完整性不降级：成功调用仍必须有可复算的四类 token 用量，且不超过预授权上界。
- 保留安全边界：认证头隔离、凭据擦除、跨协议不转换、正文不落盘全部不变。

不解决：跨协议转换、`/v1/models` 目录端点、网关侧会话或响应存储、按请求参数的动态预授权。

## 候选方案

### 方案一：保留入口白名单，逐字段按需放开

可以继续用白名单精确控制成本上界，但每支持一个上游新字段都要改平台代码；白名单本质上是把“上游协议”变成“平台协议子集”，与“原生透传、不做格式转换”的产品原则长期冲突，且预授权公式并不依赖这些字段。

### 方案二：入口完全不管形状，结算层拒绝不可计价用量

请求与响应原样转发；网关只解析模型 ID、流式标记、Chat 选项数、语义提交点、终止事件和四类 token 用量。用量缺失、矛盾、越界或含公式无法计价的额外计费维（非零 `server_tool_use`、音频/图片 token、1h 缓存写入、Gemini 非 TEXT 模态）时，该次尝试不作为成功结算，按普通失败回退或零收费终结。

### 方案三：为服务端工具等维度扩展计价公式后再放开

长期正确，但需要上游计费维度的目录化价格模型与新的预授权公式，远超本次纠正范围。

## 决定

采用方案二。

- 删除请求形状白名单：请求除 canonical→upstream 模型 ID 重写、Chat 流式注入 `include_usage=true`、凭据与安全头隔离外原样转发；不再强制 `service_tier=default` 或 `include_obfuscation=false`；`anthropic-version` 仍要求 `2023-06-01`，但 `anthropic-beta` 原样透传。
- 成功响应与 SSE 事件不再按封闭字段表检查：网关只识别错误 envelope、语义提交点、终止事件与用量；未知字段与未知事件透传，嵌套 `previous_response_id`/`store` 原样下行。
- 计费边界全部移到用量抽取：四类 token 必须完整、非负、互相一致且不超过 `2 × context_window`；未知用量字段忽略；公式无法计价的额外计费维使该次调用不成功扣款。
- 预授权、快照、提交点、幂等结算与恢复状态机（ADR-0010）不变。

## 后果

### 正面影响

- 客户端可以使用上游支持的任意原生能力（会话续接、多候选、多模态、beta 特性、真实 Responses 流式事件），不再被平台协议子集拦截。
- 平台对上游协议演进免维护：新增字段与事件自动透传。
- 计费拒绝点与计价能力一一对应：公式能算什么就收什么，算不了的明确不成功扣款。

### 负面影响与成本

- 使用了额外计费维度的调用会在结算期失败：客户端可能已收到内容但调用被记录为失败且零收费；这是“无法计价不结算”的直接代价。
- 服务端工具、音频/图片输出等能力在被目录计价化之前不可作为成功调用使用（会稳定失败回退）。
- 上游返回异常形状时失败原因从入口 400 变为结算期错误码，排查路径变化。

### 风险与缓解措施

- **免费用量风险**：语义内容已交付但结算失败的调用不收费。缓解：该路径本就存在于 ADR-0010 的“提交后无法结算”状态机（显式待恢复、零收费），不是新敞口；运营总览的成功率与漏斗指标可以观察其占比。
- **滥用不可计价维度获得免费输出**：缓解：调用事实、尝试与错误码全部持久化，管理员可按错误码下钻共享者与消费者；必要时在渠道层治理。
- **用量被上游少报**：与白名单时代相同，靠 `2 × context_window` 预授权上界与结算校验兜底。

## 验证方式

- 网关单元测试：原生形状（`previous_response_id`、`store`、`n=2`、`candidateCount=2`、多模态输入、`anthropic-beta`）透传到上游并正常结算；未知用量字段被忽略；不可计价维度（非零 `server_tool_use`、音频 token、1h 缓存、非 TEXT 模态）不成功扣款。
- 既有计费、提交点、回退、凭据擦除、幂等结算与并发测试全部保持通过。
- 生产发版后对 `POST /v1/responses` 的 `stream:true` 与 `previous_response_id` 做现场验收。
