# ADR-0043：持久跟踪后台 Responses，按可靠推理分量结算

- 状态：已通过
- 日期：2026-10-16

## 背景

后台创建返回 queued 时，上游尚未给出最终用量；把第一次 HTTP 返回作为结算点会漏账。后续 response ID 不能像新请求一样路由，否则会查询错误渠道或以另一把凭据访问。Advisor 与图像工具也不能套用外层模型价格，多个推理轮次合并后选上下文档位会错误提价。

## 决定

为后台任务持久保存归属与冻结的路由、凭据密文和价格元数据，跟踪到终态后沿用同步原子记账。任务继续占用在途槽，重启恢复；读取和取消必须持有创建时同一 Key，且只访问原渠道与原凭据。后台数据不保存正文，原凭据密文使用现有渠道 AAD 与密钥环。容量、轮询和读取并发必须有界，达到截止时间尝试取消。

以可靠推理分量分别选模型、条件价与地域，只在合并精确费用后进行一次渠道成本和一次手续费取整，不改变零和账本边界。工具附加费暂不收取；观察到的工具次数不形成额外账本分量。

## 取舍

增加后台任务持久状态，换取重启可恢复。保留后台访问元数据也意味着旧凭据解密 key 不能只因渠道已经换 Key 就删除；上游取消原 Key 后查询可能失败，任务到时限关闭。响应 ID 登记前的崩溃依然无法恢复。本次不接入厂商账单对账，不将可观察费用等同于完整厂商账单。

## 替代关系

细化 ADR-0035 的事后结算：普通调用仍以转发结束为结算点，已登记后台调用延后到任务终态。ADR-0012 的首命中选档仍有效，选择单位为每次可靠推理。ADR-0039 的单实例约束、ADR-0040 的普通请求快照读取与 ADR-0036 的固定出站边界保持有效。
