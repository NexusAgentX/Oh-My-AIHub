# ADR-0033：前端采用贴纸风视觉、双主题与自托管字体

- 状态：已通过
- 日期：2026-10-10
- 关联内容：[Epic #293](https://github.com/NexusAgentX/Oh-My-AIHub/issues/293)、[Feature #294](https://github.com/NexusAgentX/Oh-My-AIHub/issues/294)、ADR-0019、`DESIGN.md`

## 背景

ADR-0019 把视觉方向定为“现有风格精修”：墨色主按钮、芥末黄只作点缀、不做暗色主题。上线后用户反馈：
- 界面看久了显得简陋，下拉框、复选框仍是浏览器原生样式。
- 半夜用手机浏览太亮。
- 手机端体验差。

维护者喜欢芥末黄，希望品牌感明显增强。

约束：
- Nginx 的 CSP 只允许同源的脚本、样式与字体：不允许内联脚本，`font-src 'self'`。
- 产品主要在中国大陆使用，Google Fonts 等外部字体服务不稳定。
- 中文字体完整文件有数 MB。

## 候选方案

**视觉方向**
1. **精修现有风格并加暗色**：改动最小，品牌感仍弱。
2. **暖纸色加局部贴纸**：只有余额卡、徽标等少数元素做成贴纸，与其余组件的风格不统一。
3. **全站贴纸风（选定）**：
   - 纸面点阵，芥末为主色，2px 墨线配不模糊的硬投影。
   - 胶囊控件，圆体粗字的标题与数字，糖果色数据块。
   - 风格统一，品牌辨识度高，但改动覆盖全部组件。

**主题切换**
1. **只用 `prefers-color-scheme` 媒体查询**：不需要脚本，但用户无法覆盖系统设置。
2. **`<html data-theme>` 加首屏前脚本（选定）**：支持跟随系统、浅色、深色三种模式，CSS 里只有一个深色块。

**字体**
1. **外部 CDN**：违反 CSP，在国内不可靠。
2. **自托管（选定）**：Baloo 2 与源泉圆体都是 SIL OFL 1.1 许可。中文按 `unicode-range` 切片，浏览器只下载页面用到的字。

## 决定

1. **视觉语言**：全站采用贴纸风。
   - 规则写在仓库根目录的 `DESIGN.md`。
   - `frontend/src/styles/tokens.css` 仍是唯一取值来源；颜色按用途命名，组件只引用 token。
   - 借鉴 codex-resets.com 公开界面的风格，不复用它的样式代码、色值与标志性组件。
2. **双主题**：
   - token 为浅色与深色“墨夜”各给一套值，`<html data-theme>` 是唯一切换点。
   - 组件不写主题分支；需要分支说明缺一个 token。
   - 模式为跟随系统、浅色、深色。偏好保存在本机 `localStorage`，不随账户同步。
   - 因 CSP 不允许内联脚本，首屏前的主题由独立脚本 `public/theme-init.js` 设置。之后由 `src/theme/theme.ts` 负责切换、跟随系统与 `theme-color`，两者的规则由测试保证一致。
   - 第三方组件把自身颜色变量映射到 token。
3. **字体自托管**：
   - 拉丁字母与数字用 Baloo 2，中文标题用源泉圆体，正文与代码继续用系统字体。
   - 字体文件随前端镜像发布，许可随前端部署。不使用外部字体服务。
4. **与 ADR-0019 的关系**：
   - 取代 ADR-0019 决定第 2 条中的视觉约定：墨色主按钮、芥末黄只作点缀、卡片 12 与按钮 9 的圆角、不做暗色主题。
   - 继续有效：token 是唯一来源、只引用变量的规则，以及 ADR-0019 的其余决定。

## 后果

**收益**
- 品牌辨识度明显提高。
- 深色主题解决夜间刺眼的问题。
- 原生控件统一自绘，跨浏览器一致。

**成本**
- 每个颜色要维护两套值，新增颜色时两套都要验算对比度。
- 首屏多一个约 1 KB 的同步脚本。
- 字体增加下载量：Baloo 2 每个字重约 19 KB，中文按页面实际用字下载切片。
- 全站组件需要重做，分多个 PR 落地。中间状态不单独发版。

**风险与缓解**
- **首屏闪白**：由同步脚本在绘制前设置主题。
- **对比度不足**：文字对比度不低于 WCAG AA，`DESIGN.md` 要求浅深两套都验算。
- **字体加载失败**：回退到系统字体，`font-display` 保证文字可见。
- **第三方组件不跟随主题**：把它们的颜色变量映射到 token，并在截图验收中覆盖。

**验证**
- `src/theme/theme.test.ts` 覆盖模式解析、持久化、跟随系统，以及与首屏脚本的一致性。
- 界面按 `DESIGN.md`，在桌面与窄屏、浅色与深色四组截图下验收。
