# ADR-0031：论坛附件采用受限 PostgreSQL 存储并继承内容权限

- 状态：已通过
- 日期：2026-10-09
- 决策者：仓库维护者
- 关联内容：[Epic #238](https://github.com/NexusAgentX/Oh-My-AIHub/issues/238)、[Feature #239](https://github.com/NexusAgentX/Oh-My-AIHub/issues/239)、[ADR-0017](0017-adopt-sqlc-domain-persistence-layering.md)

## 背景

论坛面向已登录的小圈子成员，支持可管理板块和私密工单。Markdown 的图片与附件必须跟随内容权限，不能用公开静态目录绕过工单可见性。当前部署已有 PostgreSQL，尚无对象存储与相应凭据。

## 决策目标

保证论坛内容、附件绑定与删除原子一致；私密工单只对提交者和管理员可见；控制存储和内存消耗；复用已有部署与备份。首版不提供外部对象存储或跨内容附件复用。

## 候选方案

### 方案一：本地文件目录

实现简单，但数据库事务不能覆盖文件写入和删除，增加孤儿文件、备份一致性和容器卷管理成本。

### 方案二：对象存储

适合更大规模，需额外基础设施、凭据、访问签名与生命周期处理，超出当前小圈子范围。

### 方案三：受限 PostgreSQL bytea

文件与业务绑定在相同事务内，级联删除与现有数据库备份可直接覆盖；代价是增加数据库、WAL 和备份体积。

## 决定

采用方案三。附件独立存于 `forum_attachments`，正文查询只读元数据，不读取字节。每文件最多 10 MiB、每篇正文或回复最多 20 个附件、每账户全部临时及已绑定附件合计最多 100 MiB；上传在账户行锁内检查总量。上传 HTTP 请求最多 11 MiB，每账户每分钟 30 次，单进程最多同时处理 2 个上传。

附件初始只对上传者可见，有效期 24 小时；后台启动时及每小时清理超期未绑定文件。超期临时文件即使尚未物理删除也不能读取或绑定。绑定与正文在同一事务提交，只允许绑定当前编辑者自己的新上传，且只绑定到一篇正文或一条回复。编辑必须明确传递完整 `attachment_ids`；缺省/null 拒绝，空数组表示删除全部附件。已有附件允许作者或管理员保留，但不能跨内容重新绑定。删除正文、回复或主题通过数据库级联清理文件。

所有读取通过会话鉴权 API，普通讨论仅登录成员可见；工单、回复与其文件只对工单提交者和管理员可见。主题类型创建后不可变，不允许将工单转为普通帖子；复制附件 URL 不改变读取权限。普通板块可自由管理，非空板块拒绝删除。

图片仅验证通过的 PNG/JPEG/GIF 可内联，上传时检查解码尺寸（最多 2000 万像素）并执行解码验证；其他文件强制 `application/octet-stream` 下载。文件响应包含 `nosniff`、禁止缓存、同源资源策略与限制性 CSP，文件名规范化并经 MIME 格式化生成下载头。

## 后果

### 正面影响

- 不新增运行时依赖、服务或凭据。
- 内容与附件绑定、移除、删除保持事务一致性。
- 文件权限由所属主题决定，存储地址不能扩大可见性。

### 负面影响与成本

- 大附件会增加数据库、WAL、备份、恢复时间与网络成本；账户总量上限不等于实例总体容量上限。
- 文件响应及图片校验在内存完成；并发门禁只覆盖单进程，未来多实例需重新评估。
- 文件没有恶意软件扫描；作为普通下载的文件不被视为可信内容。

### 风险与缓解措施

- 行锁与事务约束保证并发上传不会超出账户配额、同一临时文件不能绑定到多篇内容。
- Markdown 渲染层仍需净化内容并限制 URL；本 ADR 不授权执行用户提交的 HTML 或脚本。
- 增长到明显影响数据库运行时，应新建 ADR 评估对象存储，而非提前增加双存储兼容层。

## 验证方式

领域与 HTTP 契约测试覆盖输入、权限、上传限制；真实 PostgreSQL 集成测试覆盖内容生命周期、私密工单、临时文件、事务绑定、并发配额、级联删除与审计。数据库迁移和 sqlc 生成保持一致。

## 替代关系

无。
