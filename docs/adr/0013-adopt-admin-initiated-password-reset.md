# ADR-0013：采用管理员代发的账户密码重置

- 状态：已通过
- 日期：2026-09-04
- 决策者：仓库维护者
- 关联内容：[ADR-0007](0007-adopt-invited-identity-and-server-sessions.md)、[Feature #74](https://github.com/NexusAgentX/Oh-My-AIHub/issues/74)、[SECURITY.md](../../SECURITY.md)

## 背景

受邀身份模型没有自助注册与自助找回密码，ADR-0007 在风险中明确「管理员遗忘密码后的恢复流程尚未定义，发布前另行定义」。真实试用中成员忘记密码后没有任何安全恢复途径，只能人工改库，违反安全基线。

## 决策目标

- 为忘记密码的受邀账户提供与建号一致的凭据再发放路径，不引入邮箱、验证码或自助找回。
- 保持 ADR-0007 的既有不变量：初始密码只展示一次、Argon2id 哈希、服务端会话可立即撤销、首登强制改密。
- 重置行为可审计，且不能成为绕过自身改密当前密码验证的通道。

不解决：自助找回、多因素认证、外部身份提供商、初始化窗口期的实例级恢复。

## 候选方案

### 方案一：管理员设置自定义新密码

管理员直接输入新密码。实现最直观，但把密码质量与传递责任交给管理员，容易产生弱密码和复用密码，也违背「初始凭据由平台生成」的既有规则。

### 方案二：平台生成随机初始密码，管理员代发（同建号链路）

管理员在管理账户中触发重置，平台生成新的随机初始密码并在响应中展示一次，线下交付给用户；目标账户标记必须改密并撤销全部会话。

### 方案三：仅提供 CLI 恢复工具

在服务器上用本地命令重置。不暴露新 HTTP 面，但每次恢复都需要运维介入，普通管理员无法自助完成，与网页管理台的日常操作割裂。

## 决定

采用方案二。

- 新增管理员专属端点 `POST /api/admin/accounts/{accountID}/password-reset`，位于 `requireAdmin` 之后。
- 服务端用与建号相同的随机源生成新初始密码并 Argon2id 哈希；按目标账户当前密码版本做 CAS，在单一数据库事务中提升密码版本、写入新哈希、标记 `must_change_password`、删除目标账户全部会话并写入 `account.password_reset` 审计（含操作者）。
- 不为目标账户创建新会话：发起者是管理员而非账户本人，新会话只能由用户用新初始密码登录换取。
- 重置复用改密的账户/IP 限流与 Argon2 工作槽；不允许管理员重置自己的密码，自身改密仍必须验证当前密码，避免绕过验证和自锁。
- 允许重置停用账户（与建号交付同链路）；并发密码变更只有一方成功，另一方返回冲突。

## 后果

### 正面影响

- 关闭 ADR-0007 遗留的恢复流程缺口，忘记密码不再需要人工改库。
- 与建号、首登强制改密、一次性展示和审计完全同构，用户与管理员无需学习新流程。
- 撤销全部会话使凭据泄露场景可立即止损。

### 负面影响与成本

- 误重置会立刻踢掉目标用户在线会话，前端需要两步确认与明确后果说明。
- 重置限流按操作者账户计数（8 次/15 分钟），超大批量重置需要分批进行；对低频敏感操作可接受。

### 风险与缓解措施

- **管理员滥用/误用**：重置进入统一审计表并记录操作者；限流约束频率。
- **初始密码展示后被读屏或缓存**：密码只出现在一次响应中，界面明示仅显示一次，关闭后不可回显。
- **并发竞态**：密码版本 CAS 保证重置与用户自行改密只有一方成功，冲突方明确报错。

## 验证方式

- HTTP 单元测试覆盖管理员成功重置、非管理员 403、重置自己 422、未知目标 404、密码版本冲突 409 与非法 JSON 400。
- PostgreSQL 集成测试覆盖重置后旧密码失效、新密码登录且强制改密、目标旧会话立即失效、审计记录操作者，以及陈旧密码版本重置冲突。
- 前端单元测试覆盖 API 客户端路径与请求体契约；浏览器验收覆盖两步确认与一次性展示。

## 替代关系

无；本决策填补 ADR-0007 明确留空的恢复流程，不改变其既有结论。
