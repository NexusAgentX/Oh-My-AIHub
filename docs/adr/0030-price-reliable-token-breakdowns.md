# ADR-0030：以可靠 token 细分与实际响应事实定价

- 状态：已通过
- 日期：2026-10-08
- 决策者：维护者授权范围内的 AI 执行团队
- 关联内容：[#190](https://github.com/NexusAgentX/Oh-My-AIHub/issues/190)、[ADR-0012](0012-adopt-tiered-model-pricing-and-pricing-formula-v2.md)、[ADR-0027](0027-adopt-transparent-gateway-with-post-hoc-billing.md)

## 背景

四价不能表达混合缓存 TTL、模态价差或实际响应服务档位。

## 决策目标

准确结算可靠用量，保留透明转发、历史快照与现有预算机制；不扩展独立媒体接口。

## 候选方案

### 方案一：平铺每种细分数据库列

结构明确，但方向与模态组合需要重复扩展。

### 方案二：四桶汇总加有类型细分映射

汇总统计保持简单，细分键由领域校验，JSONB 保存可选单价。

## 决定

采用方案二。细分价未配置继承命中组的通用桶价，显式零为免费；条件档不隐式继承模型细分价。细分从汇总扣除后分别加权，统一舍入。缺失或矛盾明细保留可靠汇总按通用价，账单显示原因，不猜交集或新增阻断。

实际服务档位含协议前缀；百炼条件只用于其实际思考输出语义，不把 OpenAI reasoning_tokens 普遍解释为收费模式。未知事实不匹配。OpenAI 推理已含输出；Gemini thoughts 并入输出但留为模态细分之外的通用余量。Anthropic 增量缺失保留前值但重新校验；完整累计用量替换旧细分。

快照保存当次价格与事实，后续模型编辑或删除不改写历史。区域/speed 条件、Gemini 工具提示独立计价、工具/容器/存储附加费尚未覆盖。

## 后果

### 正面影响

支持可靠 TTL、模态与服务档位，不重复计费，统计和预算机制不变。

### 负面影响与成本

不可靠上游无法精确细分收费；后台及账单必须显示限制。

### 风险与缓解措施

逐项扣减防溢出和重叠，未知与零分开；测试流式替换、TTL增量、服务降级及历史快照。

## 验证方式

领域和采集测试，PostgreSQL 真实结算及快照测试，实际后台保存读取验收。

## 替代关系

扩展 ADR-0012 的维度，保留首个条件命中及舍入规则。
