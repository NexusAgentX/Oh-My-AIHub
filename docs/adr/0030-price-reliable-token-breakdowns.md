# ADR-0030：以可靠 token 细分与实际响应事实定价

- 状态：已通过
- 日期：2026-10-08
- 决策者：维护者授权范围内的 AI 执行团队
- 关联内容：[#190](https://github.com/NexusAgentX/Oh-My-AIHub/issues/190)、[ADR-0012](0012-adopt-tiered-model-pricing-and-pricing-formula-v2.md)、[ADR-0027](archive/0027-adopt-transparent-gateway-with-post-hoc-billing.md)

## 背景

模型价格原来只有四个价：输入、输出、缓存写、缓存读。它们表达不了以下几类真实计费：

- 同一请求里混合不同 TTL 的缓存写入，例如 Anthropic 的 5 分钟与 1 小时缓存。
- 不同模态的价差，例如音频、图片、视频 token 与文本 token 单价不同。
- 按实际响应的服务档位计费，例如 OpenAI、Gemini 的 service tier。实际档位可能与请求的不同。

## 决策目标

- 准确结算可靠的用量。
- 保留透明转发、历史快照与现有预算机制。
- 不扩展独立的媒体接口。

## 候选方案

### 方案一：每种细分平铺为数据库列

结构明确，但方向（输入、输出、缓存）与模态的组合很多，每加一种都要重复扩展。

### 方案二：四桶汇总加有类型的细分映射

四个汇总桶保持不变，统计依旧简单；细分用量的键由领域层校验；可选的细分单价存 JSONB。

## 决定

采用方案二。

1. **细分价的继承**：
   - 细分价未配置时，继承所命中价格组对应通用桶的价格；显式填 0 表示免费。
   - 条件档不会隐式继承模型（默认档）上配置的细分价。
2. **计价**：细分用量先从对应汇总中扣除，再与剩余的通用用量分别加权，最后统一舍入。每个 token 只计一次。
3. **明细缺失或矛盾**：
   - 保留可靠的汇总，按通用价计费，账单显示原因。
   - 不猜测交集，例如不自行推算音频与缓存的重叠。
   - 不因此新增阻断。
4. **按实际响应事实匹配条件**：
   - 服务档位的取值带协议前缀，按实际响应匹配。
   - 百炼的思考条件只对应它实际的思考输出语义，不把 OpenAI 的 `reasoning_tokens` 普遍解释为一种收费模式。显式配置百炼条件档是采用该语义的唯一来源；通用思考观察不表示百炼身份。
   - 未知的事实不匹配任何条件。
5. **各协议的用量口径**：
   - OpenAI 的推理 token 已经包含在输出中。
   - Gemini 的 thoughts 并入输出，但作为模态细分之外的通用余量计价。
   - Anthropic 流式增量缺少某项时保留前值，但重新校验；收到完整的累计用量时，替换旧的细分。
6. **快照**：保存当次的价格与事实，后续编辑或删除模型不改写历史。
7. **尚未覆盖**：区域与 speed 条件、Gemini 工具提示 token 的独立计价，以及工具、容器、存储附加费。

## 后果

### 正面影响

支持可靠的 TTL、模态与服务档位定价，不重复计费，统计与预算机制不变。

### 负面影响与成本

上游不提供可靠明细时无法精确细分收费；后台与账单必须显示这一限制。

### 风险与缓解措施

逐项扣减时防止溢出与重叠，未知与零分开表示。测试覆盖流式替换、TTL 增量、服务档位降级与历史快照。

## 验证方式

领域与采集测试、PostgreSQL 真实结算与快照测试，以及在实际后台保存和读取的验收。
