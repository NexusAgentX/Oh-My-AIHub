# ADR-0032：按有序提供商白名单同步并保护模型引用

- 状态：已接受
- 日期：2026-10-08
- 决策者：维护者与 Agent
- 关联内容：Feature #205、ADR-0031

## 背景

全量导入数千模型不符合管理员需要，带哈希的本地名称也不便调用。维护者要求明确选择提供商：同名模型按白名单顺序选择来源，仅本地模型 ID 使用源键最后一段，显示名保留完整源键。已有 v0.9.0 数据库包含旧名称及调用引用，需要原地升级。

## 决策目标

限制目录范围、提供确定性的同名决策、精确保留历史与配置引用；不改价格映射，不新增调用端点。本次交付不包含生产发布授权。

## 候选方案

### 方案一：继续以完整键的哈希区分模型

可完全保留提供商差异，但不能提供用户要求的简短调用名，也无法控制目录规模。

### 方案二：有序白名单选择来源，旧引用保留原名

目录 ID 可读且稳定。管理员明确接受优先级变化会改变同名模型的来源和定价；旧 ID 则按引用状态保留或清理。

## 决定

采用方案二，取代 ADR-0031 关于完整源键生成哈希 ID、不同提供方始终分开建模的部分。其余价格精度、缺价隔离、opt-out 与异步同步原则保留。

`catalog_sync.providers` 保存有序提供商白名单；初始空数组且 `providers_configured=false`，不会导入或整理现有目录。管理员显式保存（包括空数组）后，下一次成功同步才整理；空数组不代表全选。提供商选项来自完整抓取中当前支持的 chat/Responses 资料，不根据 key 前缀猜测 provider。

候选按 provider 的白名单位置、完整 source key 字典序排序，同一短 ID 只选择第一条并记录其他同名候选。ID 取最后一个 `/` 后的完整部分，允许安全字符 `:` 与 `@`，不加哈希；显示名保留完整 source key。Gemini 按最后一个冒号拆分动作。改变提供商顺序后，同一本地 ID 可改用新的来源和价格；无法映射的新价格仍保留最后有效价格及实际价格来源键。

`model_sources` 改用本地 model_id 主键，完整 source_key 可重复，因此同一来源可以对应保留的旧 ID 和新的短 ID。整理只删除没有渠道、调用/账单、路由、API Key 显式引用的同步管理模型。手工与 opt-out 始终保留；有引用的旧 ID 保持原名与最后价格，显示保留原因。上游暂缺且 provider 仍在白名单时仅标记 missing，不视为清理授权。

用户删除写入独立 `catalog_deleted_models`，按本地 ID 及源末段阻止换提供商后复活；普通白名单排除和手工冲突不是删除墓碑。旧版本 ignored/conflict 记录不转成删除墓碑，后续成功整理时移除冲突标记。

抓取前记录配置版本，应用事务里重新加锁核验，包含改后又改回的情况。整理期间锁住 calls/API keys 写入；API Key 写入先取表写锁，再在同一事务验证并锁住显式目标模型，避免服务层预校验结果过期。渠道与路由依赖外键并在模型行锁内检查。网关先插入调用再读取模型，新请求在整理后重新验证目录。

新增 `0002` 迁移原地添加配置/报告/墓碑并调整来源键；不重写基线、不重建数据库，不重命名被引用模型。回滚遇到新字符 ID 或重复来源键会明确拒绝，避免丢失数据。

## 后果

### 正面影响

- 管理员可控制目录规模和提供商优先级。
- 新调用名简洁，显示名仍能辨认来源；引用与历史不会被自动改名破坏。

### 负面影响与成本

- 被引用旧名称可能与新短名称同时存在，需管理员后续整理。
- 每日整理事务会短暂等待或阻塞调用记录/API Key 写入；只有成功抓取并校验配置后才进入该事务。

### 风险与缓解措施

- 来源切换会影响费用：提供商顺序显式可见，实际价格来源和应用汇率可追溯。
- 源缺行、下载失败或配置并发变化不得删除目录；采用保留状态与全事务回滚。

## 验证方式

候选顺序/末段字符单测；原地迁移、引用保护、opt-out、删除墓碑、来源切换、配置 ABA 和过期 Key 引用数据库测试；旧库升级后的桌面/窄屏真实界面验收。

## 替代关系

部分取代 ADR-0031 的命名和不同提供商建模规则；保留其计价及本地控制规则。
