# ADR-0006：采用 PostgreSQL、Goose 与九位定点金额

- 状态：已通过
- 日期：2026-09-02
- 决策者：仓库维护者
- 关联内容：[Feature #21](https://github.com/NexusAgentX/Oh-My-AIHub/issues/21)、[Feature #18](https://github.com/NexusAgentX/Oh-My-AIHub/issues/18)、[ADR-0005](0005-adopt-centralized-zero-sum-ledger.md)

## 背景

受邀账户、会话、模型目录和后续零和账本需要共享事务边界、唯一约束、行锁、审计与精确金额表示。内存状态或无事务文档存储不能可靠支撑首次管理员并发创建、改密撤销会话、信用限制、幂等结算和 C2C 冻结。模型价格还可能包含小于 0.01 积分的 token 单价，不能由二进制浮点数承担最终结算。

## 决策目标

- 为身份、目录、账本、渠道、调用和 C2C 提供同一套强事务持久化基础。
- 让数据库结构以可审阅、可重复、可在应用启动前独立执行的方式演进。
- 所有金额和价格拥有确定精度、可逆字符串表示和溢出保护。
- 开发与 Compose 环境保持简单，不提前引入分布式状态组件。

本决策不确定生产高可用、备份恢复、托管数据库供应商或跨区域复制方案。

## 候选方案

### 方案一：内存状态或嵌入式数据库

启动简单，但多进程、并发事务、运行时持久性和生产运维能力不足，后续账本迁移成本高。

### 方案二：PostgreSQL、SQL-only Goose 与九位定点整数

PostgreSQL 提供事务、约束、锁、数组、JSONB 和成熟运维生态；Goose 直接执行嵌入 Go 二进制的 SQL 迁移；金额统一保存为 `BIGINT` 纳积分，API 使用十进制字符串。

### 方案三：ORM 自动建表与数据库定点小数

ORM 能减少部分样板，但容易把数据库约束和迁移差异隐藏在运行时。数据库 `NUMERIC` 可表达任意精度，却会把精度、舍入与范围分散到查询和驱动边界。

## 决定

采用方案二。

- PostgreSQL 18 是首版唯一事务状态数据库。
- 数据库结构由 SQL-only Goose 迁移管理；迁移嵌入后端构建产物，并由独立 `migrate` 命令在服务启动前执行。
- 1 积分等于 1,000,000,000 纳积分。持久化金额和价格使用有符号 64 位整数，Go 领域层使用同尺度类型，JSON API 使用最多九位小数的十进制字符串。
- 禁止使用 `float32` 或 `float64` 作为最终余额、价格、费用、冻结或分录金额。
- 本 ADR 只确定存储尺度。Feature #18 与 #20 必须另行固定“基准价 × token 用量 ÷ 1,000,000”及倍率、手续费的运算顺序、舍入方向和中间溢出策略，并把规则保存为可重放快照。
- 首版所有需要原子一致性的业务状态放在同一数据库；除非取得容量证据，不引入额外数据库、消息队列或分布式事务。

## 后果

### 正面影响

- 身份、账本和 C2C 可以共享数据库事务、唯一约束和锁。
- 迁移文件是可审阅的架构事实，容器和本地环境执行同一迁移入口。
- 十进制字符串与整数换算可保持精确，九位小数足以表达基准价和后续按 token 计费。
- PostgreSQL 的约束可在服务代码之外继续保护不变量。

### 负面影响与成本

- 所有开发和测试环境都需要可用的 PostgreSQL。
- 64 位九位定点数的绝对范围约为 92 亿积分，需要在输入边界拒绝溢出。
- 迁移需要显式编写和验证，数据库主版本升级也需要运维计划。

### 风险与缓解措施

- **迁移与服务版本不一致**：Compose 以一次性迁移完成为后端启动条件，CI 和集成测试先运行相同迁移。
- **金额溢出或精度丢失**：集中解析/格式化，覆盖 `int64` 极值和九位精度测试，API 不接受更多小数位。
- **数据库成为单点**：首版接受单实例边界；发布前补充备份、恢复和健康告警，不在缺少真实负载时提前分布式化。
- **开发凭据进入生产**：Compose 默认值只用于本地；互联网部署必须注入独立数据库密码并限制数据库网络入口。

## 验证方式

- 在真实 PostgreSQL 上从空 schema 执行全部迁移，并运行身份与模型目录集成测试。
- 并发创建初始管理员只能成功一次；账户、会话、模型和审计约束可被测试观察。
- 金额单元测试覆盖九位小数、非法格式以及 `int64` 正负边界。
- `docker compose config --quiet` 和健康检查证明启动依赖与数据库连通性有效。
