# ADR-0023：删除 C2C 买单，只保留卖单

- 状态：已通过
- 日期：2026-10-07
- 决策者：项目维护者与 AI 产品团队
- 关联内容：Epic #158、Feature #159、[ADR-0011](0011-adopt-c2c-order-trade-hold-state-machine.md)

## 背景

ADR-0011 让 C2C 市场同时支持卖单与买单：卖单发布时以父持有冻结全部挂牌积分；买单不预先冻结，卖家承接时才为本次成交创建独立的 `asset_reservation`。两种订单共用交易状态机，但创建、承接、取消、放行、行情盘口和界面都要为两条路径分别实现与测试。

维护者在 2026-10-07 判断：小圈子规模下买单几乎没有人承接，双边盘口只增加订单状态机、收款方式校验（买单只要求联系方式、不允许收款码）、行情（买一、价差）和界面的复杂度。项目仍是未发布中间态，不需要保留兼容层。

## 决策目标

- C2C 只有卖单：卖家挂单并冻结积分，买家承接部分数量，平台外付款，文字付款声明，卖家放行或争议，管理员裁决。
- 系统在数据库层面再也不能产生买单，应用代码不保留买单分支。
- 已终结的历史买单、交易与账本保持不变，零和与持有投影不受影响。
- 存在未终结买单状态时不静默取消、不改写账本，迁移必须明确失败。

不改变部分成交、单笔最小/最大数量、多收款方式、文字争议、管理员裁决、180 天私密清理和账本持有规则。

## 候选方案

### 方案一：迁移时自动取消全部未终结买单

迁移内释放买单下交易的持有并取消买单。这会在 SQL 迁移中重复实现账本释放语义，绕过幂等命令与事件，违背账本只通过服务层变化的约束。

### 方案二：删除 `side` 列并清理买单行

列表面最简洁，但历史买单没有父持有，删除 `side` 后无法与卖单区分，既有的 `parent_hold_id` 约束与按卖单校验的触发器也会把它们判为不一致；删除历史行违反订单与交易历史不可物理删除的约束，也会使账本引用失去业务来源。

### 方案三：前置检查并保留历史行，收紧写入约束

迁移先检查是否仍有未终结买单状态，有则失败；通过后保留 `side` 列与历史买单行，只禁止此后写入非卖单。应用代码删除全部买单分支。

## 决定

采用方案三。

1. 迁移 `0009` 开头检查：存在 `open` / `allocated` 买单，或买单下处于 `awaiting_payment` / `paid` / `disputed` 的交易时，抛出带数量与处理指引的异常使迁移失败；管理员须先在旧版本中取消或处理。检查与后续变更位于同一迁移事务，失败不留下部分结构。
2. 检查通过后：`side` 列保留并设默认值 `sell`，以 `CHECK (side = 'sell') NOT VALID` 取代原约束，只约束此后的写入，历史买单行不被改写；删除买单盘口索引；订单与交易的延迟校验函数改为只校验卖单与卖单交易，历史买单行不再被重新校验。迁移不可逆（`Down` 明确报错，需回滚时从备份恢复）。
3. 应用层删除 `side` 概念：创建挂单不再接受方向，订单、交易与行情响应不再含 `side`、`order_side`、`buy_orders`、`best_bid_fen`、`spread_fen`；钱包恢复动作删除 `create_buy_order`；运营指标的订单计数不再按方向分组、报价不再含买一与价差。用户的订单列表不展示历史买单，历史买单下的交易按买家与卖家身份保持可读。
4. 承接卖单始终使用父持有中的数量，不再为单笔交易创建独立持有；ADR-0011 决定第 2 条（买单持有）与相关的双路径约束由本 ADR 取代，其余决定（父持有恒等式、状态机、幂等、锁序、私密资料保护）继续有效。

## 后果

### 正面影响

- 订单状态机、承接路径、收款方式校验、行情和界面只剩一条路径，测试与维护成本减半。
- 迁移不改写账本，历史买单仍可审计。

### 负面影响与成本

- 数据库保留一个只服务历史行的 `side` 列与 `NOT VALID` 约束；历史买单不在用户订单列表中展示。
- 需要买入积分的用户只能承接他人的卖单。
- 迁移不可逆，升级前若存在未终结买单必须先在旧版本中处理。

### 风险与缓解措施

- 升级失败风险：迁移前置检查给出明确提示，且不产生部分变更；集成测试覆盖失败与成功两种情形。
- 历史行被后续代码误当卖单：校验函数显式跳过非卖单行，用户订单查询仅列出卖单。

## 验证方式

- PostgreSQL 集成测试：迁移在存在 `open` 买单或买单下未终结交易时失败，且账本与行不变；仅有终态历史买单时成功，账本条目、余额与持有投影不变，之后新写入买单被约束拒绝。
- 卖单创建、部分承接、付款声明、放行、取消与争议裁决的既有集成测试保持通过。
- 契约测试确认响应不再含买单字段。

## 替代关系

取代 [ADR-0011](0011-adopt-c2c-order-trade-hold-state-machine.md) 中与买单有关的部分（决定第 2 条及各处“买单”相关表述）；ADR-0011 的其余内容继续有效。
