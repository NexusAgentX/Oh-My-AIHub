# ADR-0039：按单实例部署，运行时状态放在进程内

- 状态：已通过
- 日期：2026-10-11
- 决策者：维护者
- 关联内容：[ADR-0006](0006-adopt-postgresql-goose-and-fixed-point-amounts.md)、[ADR-0007](0007-adopt-invited-identity-and-server-sessions.md)、[ADR-0029](0029-compute-observability-on-demand-with-internal-metrics.md)、[ADR-0031](0031-store-forum-attachments-in-postgresql.md)、[ADR-0035](0035-adopt-transparent-gateway-v2.md)、[ADR-0036](0036-adopt-credential-startup-check-and-pinned-egress-pool.md)

## 背景

ADR-0006 定下“首版不引入额外数据库、消息队列或分布式事务”。此后多篇 ADR 都把“单实例”当作前提，却从没作为决定记录下来：

- 网关的冷却、并发、每分钟请求数、每日收入上限、连续失败计数与 Key 已用额缓存都在进程内（ADR-0035）。
- 观测的实时流与指标订阅进程内事件总线（ADR-0029）。
- 登录与改密限流、Argon2 工作槽在进程内（ADR-0007）。
- 论坛上传并发门禁在进程内（ADR-0031）。
- 后台任务都在 `cmd/server` 内运行：超时调用清理、C2C 付款超时、汇率同步、指标刷新、附件清理、错误文本清理。

2026-10-11 确定网关走“热路径数据放进内存”的性能路线（连接池、DNS 缓存、凭据明文缓存、只读数据快照、余额缓存）。这会进一步加深对单进程的依赖，需要把它明确为决定，并写清什么时候重新评估。

## 候选方案

1. **单实例，运行时状态放在进程内（选定）**：没有额外组件；进程内失效即时、简单；不能水平扩展，重启会清空运行时状态。
2. **多实例，共享状态放进 PostgreSQL**：限流与冷却改成数据库行或咨询锁，缓存失效走 `LISTEN/NOTIFY`，后台任务选主。热路径要多次往返数据库，与性能目标冲突；当前也没有容量证据需要它。
3. **多实例，引入 Redis 等共享组件**：多一个需要部署、备份与监控的状态组件，违背 ADR-0006。

## 决定

采用方案 1。

- **部署形态**：
  - 一个后端进程（`cmd/server`）加一个 PostgreSQL，由 Compose 编排：数据库、一次性迁移、后端，以及前端 Nginx。
  - 唯一公网入口是外层 TLS 反向代理。前端只绑定宿主机回环地址；后端不发布端口；指标端口只在内网。
- **进程内状态**：
  - 以下状态只在后端进程内维护：渠道运行时状态、预算与在途计数、事件总线、限流与 Argon2 工作槽、上传并发门禁。
  - 以后加入的热路径缓存同样放在进程内，包括连接池与 DNS 缓存、凭据明文缓存、只读数据快照、余额缓存。
  - 后端是唯一写入数据库的进程，所以缓存在写事务提交后于进程内失效，另以定期全量刷新兜底。
- **后台任务**：都在后端进程内运行，不做选主。
- **重启的影响**：发布或重启会中断在途调用，这些调用不收费（ADR-0035 规则 9）。冷却、计数与缓存清零后重新累计或加载。
- **禁止多副本**：不得同时运行多个后端副本。否则限额与冷却按副本各算一份，缓存失效互相看不见，后台任务会重复执行。
- **重新评估的条件**：出现以下任一情况时，新建 ADR 评估方案 2 或 3。
  - 实测负载超过单进程容量（以网关性能基线为依据）。
  - 可用性目标要求不中断发布或故障切换。

## 后果

- **收益**：
  - 部署与运维只有两个状态组件：后端进程与 PostgreSQL。
  - 热路径可以完全走内存，缓存失效即时且容易验证。
- **成本**：
  - 不能水平扩展。
  - 发布和重启会中断在途调用并清空运行时状态。
  - 进程是单点；数据库仍需备份与恢复演练。
- **风险与缓解**：
  - **误部署多副本**：部署手册与本 ADR 明确禁止；生产由受限发布脚本以单个 Compose 项目部署。
  - **单进程容量不够**：网关性能基线给出容量数据，达到重新评估条件时新建 ADR。
- **验证**：Compose 配置中后端只有一个服务、一个副本；部署手册与本 ADR 一致。

## 替代关系

无。本 ADR 把 ADR-0006 及之后各 ADR 隐含的单实例前提明确为决定，不改变它们的结论。
