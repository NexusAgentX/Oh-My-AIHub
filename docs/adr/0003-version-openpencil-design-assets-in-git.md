# ADR-0003：将 OpenPencil 可编辑设计源文件作为 Git 一等资产

- 状态：已通过
- 日期：2026-09-01
- 决策者：项目维护者
- 关联内容：Epic #3、Feature #5、`DESIGN.md`、`design/README.md`

## 背景

项目维护者希望由 AI 负责设计执行，但要求 AI 使用专业设计工具，而不是只在对话中描述界面或直接凭感觉写前端。同时，设计稿必须像代码一样成为仓库资产，能够在同一个任务中评审、追溯、分支和回滚。

仅保存截图会丢失图层、组件、交互状态和可编辑语义；仅保存云端设计链接会把关键事实放到 Git 权限、历史和离线能力之外；只提交代码又会让设计意图无法独立评审。项目需要一个不依赖个人账号或单台机器的设计事实来源。

## 决策目标

- 让具体设计拥有可编辑、可追溯、可回滚的 Git 源文件。
- 让不安装设计工具的评审者也能快速查看视觉结果。
- 让设计、实现和验收处于同一个 Issue、分支和 Pull Request 边界。
- 让 AI 通过专业工具操作设计，同时由人类保留产品方向和关键设计选择权。
- 避免凭据、真实用户数据、本机路径和个人云端状态进入仓库。

本决策不定义产品功能，也不要求所有纯后端或无视觉影响的任务产生设计资产。

## 候选方案

### 方案一：只保存截图或导出的静态文件

优点是查看方便；缺点是不可编辑、结构不可检查，无法作为后续设计迭代的可靠输入。

### 方案二：设计保存在独立云端或独立仓库

优点是可以使用外部协作能力；缺点是权限、版本和任务边界与代码分离，离线与长期可访问性依赖外部服务，设计和实现容易漂移。

### 方案三：在主仓库提交 OpenPencil 源文件和同名预览

OpenPencil `.op` 保存可编辑结构，PNG 保存易审阅结果；二者和代码进入同一个 Git 工作流。专业工具负责生成与修改，仓库检查负责基本完整性和可移植性。

## 决定

采用方案三。

OpenPencil 是本项目主要 UI/UX 设计工具。具体设计的权威源文件保存在 `design/sources/<stable-name>.op`，由 OpenPencil 从同一源文件导出的预览保存在 `design/previews/<stable-name>.png`。`DESIGN.md` 继续作为通用视觉 Token 与规则的事实来源，`.op` 负责记录具体页面、流程、组件和状态。

影响用户流程、交互或视觉结果的 Feature 必须在同一个 Issue、分支和 Pull Request 中同步维护适用的 `.op`、预览、实现和验收证据。文件名使用稳定的 kebab-case，不用日期、`final`、`v2` 等后缀模拟版本；版本由 Git 历史表达。

设计必须通过 OpenPencil 创建或修改，不能手写 `.op` JSON 冒充工具设计。Agent 的设计读取、创建、修改、保存、lint 和导出只允许直接调用 OpenPencil MCP，不得把 `op` CLI 作为降级或自动化后备通道；MCP 未加载或服务不可用时，任务暂停并由维护者修复或重载会话。`op` CLI 仅作为本机接入组件保留，用于官方安装和人工版本确认。Codex 的本机 MCP 与 Skill 配置不提交仓库。

当前资产规模不引入 Git LFS。只有实际文件体积或仓库性能形成证据时，才通过新的决策评估 LFS 或拆分策略。

## 后果

### 正面影响

- 设计和代码共享 Git 的分支、差异、评审、回滚和权限模型。
- AI 可以持续操作结构化设计，人类可以通过 PNG 快速把控方向。
- 设计意图、视觉结果和工程实现可以在一个交付单元中核对。
- 不依赖单个云端链接或个人账号即可恢复项目设计资产。

### 负面影响与成本

- 每次设计变化需要同步保存 `.op` 和导出预览。
- `.op` 的文本差异未必像代码差异一样易读，视觉评审仍需要预览和工具现场检查。
- OpenPencil 当前为预发布工具，格式和客户端行为可能变化。

### 风险与缓解措施

- 源文件和预览漂移：使用同名约定、`mise run check-design` 和 PR 视觉检查。
- 工具升级破坏兼容：升级前用真实资产验证打开、保存、lint 和导出，必要时独立建立 Feature。
- MCP 不可用导致设计停工：明确暴露阻塞并由维护者修复或重载，避免 CLI 降级产生两套行为和无法复现的证据。
- 资产泄露信息：自动扫描常见凭据和本机路径，评审时检查真实用户数据和外部资源授权。
- 仓库膨胀：保持稳定文件名、只提交必要预览，达到实际阈值后再评估 LFS。
- 设计脱离实现：将源文件、预览和对应代码绑定到同一个任务与完成条件。

## 验证方式

- 仓库存在由 OpenPencil 生成、可重新打开的 `.op` 文件及同名 PNG 预览。
- OpenPencil 的最终校正和设计 lint 通过，预览经过视觉检查。
- `mise run check-design` 验证格式、配对、命名、PNG 完整性和基础安全规则。
- 后续视觉 Feature 的 PR 同时展示设计源、预览、实现和现场验收边界。
