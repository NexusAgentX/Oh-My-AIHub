# ADR-0010：采用快照化 API 网关与幂等终结状态机

- 状态：已通过
- 日期：2026-09-03
- 决策者：仓库维护者
- 关联内容：[Feature #20](https://github.com/NexusAgentX/Oh-My-AIHub/issues/20)、[ADR-0008](0008-adopt-immutable-ledger-holds-and-pricing-formula-v1.md)、[ADR-0009](0009-adopt-encrypted-upstream-credentials-and-pinned-egress.md)

## 背景

平台需要用一把消费者 Key 按固定优先级访问多个用户共享的中转渠道，并在上游配置、模型价格、资格、凭据版本和账户可用额度并发变化时仍得到可解释、可复算的结果。流式响应还引入一个不可逆边界：内容一旦交给客户端，就不能再切换渠道或假装调用从未发生；进程也可能在提交响应、保存尝试或完成账本结算之间退出。

若在调用过程中反复读取当前配置，单次调用可能混用不同时点的池、价格和凭据。若代理完成后再用普通更新扣款，崩溃、重复恢复和并发终结可能造成免费输出、重复扣款或永久持有。平台 API Key 也不能复用浏览器会话或保存可恢复明文。

## 决策目标

- 一次调用只使用一个事务时点的身份、路由、定价、凭据版本和预授权决定。
- 提交点前允许顺序回退，提交点后锁定唯一候选且不重试上游 POST。
- 成功、失败、取消、断流和进程恢复都只能产生一次确定结算结果。
- 平台 Key、上游凭据和请求、响应正文不进入持久化事实或通用投影。
- 消费者、共享者和管理员只能读取与自身业务关系匹配的调用视图。

## 候选方案

### 每次尝试读取当前配置，调用结束后直接扣款

实现较少，但无法证明多次读取属于同一时点；调用期间的编辑会让历史无法复算，结束后的独立扣款还会在崩溃或重放时产生部分完成和重复执行。

### 先复制全部请求和响应，再由异步任务对账

可以延后结算，但会持久化产品明确禁止保存的正文，并把客户端成功与账本成功拆成难以恢复的两个事实来源。

### 快照调用、预授权和幂等终结状态机

在同一个 `REPEATABLE READ` 事务内建立不可变调用快照与必要的消费授权；尝试只引用快照候选。最终状态由不可变成功尝试推导，使用调用 ID 和载荷摘要幂等地捕获、释放或记录自有渠道双分录。租约和恢复任务只重放已知终结，不重新调用上游。

## 决定

采用第三种方案：

- 平台 Key 由服务端生成，只保存 SHA-256 校验摘要、公开前缀、代次、状态和版本；创建与轮换只在对应响应展示一次完整值。轮换、启停、删除和配置编辑使用版本 CAS。
- 每把 Key 保存唯一的“canonical 模型 + 原生协议”池，池成员引用稳定报价 ID，数组顺序就是连续优先级。已加入但后来失去资格的成员可以保留配置，但新调用不会把它放入候选。
- 调用前在单个 `REPEATABLE READ` 事务中重新验证 Key、账户、池和报价资格，取得版本化凭据租约、模型价格、倍率、手续费和 formula-v1 快照，并按消费者最大净借记创建可空消费授权。
- 四个协议入口只做同协议模型别名重写与元数据还原，不做格式转换。每个候选最多发送一次 POST；只有首个语义内容或工具事件实际提交后才锁定候选。
- 非流式成功响应和流式成功终止事件都延迟到完整终态、合法用量和原子结算完成后返回。失败、取消、不完整或缺用量调用零收费并释放持有。
- 尝试、调用、结算和恢复使用数据库状态约束、行锁、唯一约束、调用 ID 与终结载荷摘要。相同终结可重放，异载荷冲突；存在已提交语义但尚未形成完整成功尝试时进入显式待恢复状态，不释放成免费输出。
- 只保存调用、尝试、价格与用量快照、状态、时延、HTTP 状态和受限原始错误字段；不保存请求正文、响应正文、请求头或凭据。共享者只看到实际尝试其报价的专属投影。

## 后果

- 单次调用可由快照和 formula-v1 复算，配置变化只影响后续调用。
- 事务、状态机、流式协议适配和恢复逻辑比普通反向代理复杂，必须保留 PostgreSQL 并发、故障注入和协议 fixture 测试。
- 结算是客户端成功终止的一部分；数据库暂时不可用时宁可不给出成功终止，也不能先输出完整成功后异步猜测扣款。
- 首版只支持固定优先级，不引入权重随机、对冲、跨协议转换或自动同候选重试。
- 真实官方 SDK 现场验收仍需要可控的已充值上游渠道和测试账户，不能由单元或本地代理测试替代。

## 验证方式

- 平台 Key 生命周期、池唯一性、优先级连续性和并发 CAS 的 PostgreSQL 集成测试。
- 快照与凭据版本并发、预授权、精确捕获/释放、自有渠道双分录、重复终结和 orphan 恢复测试。
- 四协议非流式、SSE、认证头隔离、模型映射、回退、提交点、用量、资源上限、取消和错误 envelope 测试。
- DTO 与 sentinel 测试确认完整正文、请求头和凭据不进入数据库或前端合同。
- Vite、Nginx 和 Compose 配置检查，以及四个外部协议路径的代理实测。
