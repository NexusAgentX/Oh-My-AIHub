# ADR-0036：凭据加密与启动全量校验、钉住地址的出站连接池

- 状态：已通过
- 日期：2026-10-11
- 决策者：维护者
- 关联内容：[ADR-0009](archive/0009-adopt-encrypted-upstream-credentials-and-pinned-egress.md)（被本 ADR 取代）、[ADR-0028](0028-store-platform-api-keys-reversibly-encrypted.md)、[ADR-0035](0035-adopt-transparent-gateway-v2.md)、[ADR-0039](0039-deploy-as-single-instance.md)

## 背景

ADR-0009 规定了上游凭据的版本化加密，以及“每次解析、钉住地址”的出站网络边界。到 v0.15.0，它与现状有以下出入：

- **启动校验没有实现**：ADR-0009 要求启动时逐一解密全部存活渠道凭据，任一失败就拒绝启动。实际只校验密钥环格式，缺少的密钥要到使用对应渠道、Key 或卖单时才暴露。
- **轮换流程没有工具**：ADR-0009 描述的“全部密文重加密后移除旧密钥”没有任何重加密工具支撑，备份恢复手册只能要求密钥环保留全部历史 key id。
- **密钥环用途扩大，没有记录**：
  - 同一个上游凭据密钥环后来也用于加密平台 API Key（ADR-0028）。
  - C2C 收款信息使用独立的 C2C 私密数据密钥环，没有 ADR 记录。
- **出站开销大**：每次访问都重新解析 DNS 并禁用连接复用，每个网关请求多一次 DNS 查询和一次 TCP 与 TLS 握手，上游在境外时多几百毫秒。2026-10-11 的评审确定网关要提高性能。
- **用语过时**：ADR-0009 里的“报价”“路由租约”“公开市场”“发布校验门禁”是 v0.6.0 的概念，已随重写消失。

## 决策目标

- 数据库、备份、通用 DTO 和日志都不能直接恢复或泄露以下明文：上游凭据、平台 API Key、C2C 私密数据。
- 缺少密钥或密文损坏时，启动即暴露并拒绝启动（失败关闭），而不是到使用时才发现。
- 每个出站连接只连到通过校验的地址；拒绝本机、私网、云元数据、保留地址与 OpenAI 官方端点。
- 网关转发复用连接、减少 DNS 查询，不放宽上一条。
- 不解决：托管 KMS、独立出站代理、凭据重加密工具（暂不提供）。

## 候选方案

**启动校验**

1. 只校验密钥环格式（现状）：启动快，但缺 key 要到使用时才暴露。
2. 启动时解密全部存量密文（选定）：失败关闭；启动时间随密文数量增加，当前规模可以忽略。
3. 方案 2 再加重加密命令，支持移除旧 key：轮换完整，但工作量大，而轮换很少发生，暂不做。

**网关出站连接**

1. 每次重新解析，禁用连接复用（ADR-0009）：最简单，开销最大。
2. 每次重新解析，只复用远端地址仍在本次解析结果中的空闲连接：省握手，不省 DNS。
3. 按主机缓存通过校验的地址 60 秒，连接池只向这些地址拨号（选定）：省 DNS 和握手，地址变化最多 60 秒后生效。

方案 2 与 3 都只连接通过校验的地址，安全性相同，区别只在新鲜度和性能。

**凭据明文**

1. 每次请求解密：明文不常驻内存。
2. 进程内缓存（选定）：省去每次请求的解密；维护者已接受明文常驻进程内存。

## 决定

1. **加密**：
   - 凭据使用 AES-256-GCM 加密，每次写入生成随机 nonce。数据库只保存版本、密钥 ID、nonce 与密文。
   - 密钥环从运行环境注入，格式为多个 `key-id=base64-key`；活动 key id 用于新写入。
   - 系统有两个互相独立的密钥环，禁止复用同一组密钥：

   | 密钥环 | 环境变量 | 加密对象 | 附加数据（AAD）绑定 |
   | --- | --- | --- | --- |
   | 上游凭据密钥环 | `UPSTREAM_CREDENTIAL_KEYRING` / `UPSTREAM_CREDENTIAL_ACTIVE_KEY_ID` | 渠道上游 Key；平台 API Key（ADR-0028） | 渠道 ID 或 Key ID、版本、密钥 ID |
   | C2C 私密数据密钥环 | `C2C_PRIVATE_DATA_KEYRING` / `C2C_PRIVATE_DATA_ACTIVE_KEY_ID` | C2C 收款信息 | 记录 ID 与用途 |

   - 上游 Key 不通过任何接口回显；平台 API Key 的明文只按 ADR-0028 返回给所有者。
2. **启动全量校验**：后端在开始服务之前，逐一解密仍可能被使用的全部密文：未删除渠道的上游凭据、未删除的平台 API Key、C2C 私密数据。任一失败即拒绝启动，日志只记录类型与记录 ID，不记录明文或密文。
3. **轮换**：
   - 暂不提供重加密工具。换用新密钥的方式是把新 key 加入密钥环并切换活动 key id，新密钥只用于之后的写入。
   - 旧 key id 必须永久保留在密钥环中。密钥环与数据库备份作为一个恢复集合管理。
   - 将来提供重加密工具时，另立 ADR 规定移除旧密钥的顺序。
4. **Base URL**（沿用）：
   - 只允许 HTTPS 域名、允许的端口，以及不含具体 API 资源名的根前缀。
   - 拒绝用户信息、查询、片段、IP 字面量、路径穿越和编码分隔符。
   - 永久禁用 `api.openai.com` 及其子域。
5. **地址校验**（沿用）：
   - 解析全部 DNS 候选，任一候选属于以下范围就整次拒绝：本机、私有、链路本地、组播、未指定、保留、文档、NAT64、6to4、Teredo，以及未由 IANA 分配的 IPv6 全局单播范围。
   - 实际拨号只使用通过校验的地址，目标端口必须匹配，TLS 继续验证原始域名。
6. **出站客户端**（沿用）：
   - 不使用环境代理，不跟随重定向，限制 TLS、响应头与响应体大小。
   - 默认只允许 443 端口。配置只能追加端口或禁用域名，不能解除永久禁用项。
   - 叠加管理员维护的 `settings.extra_blocked_hosts`。
7. **网关转发的连接池与 DNS 缓存**（新增）：
   - **适用范围**：只用于网关转发。渠道发现与格式测试继续使用一次性客户端，每次重新解析。
   - **DNS 缓存**：按主机缓存通过校验的地址列表，固定 60 秒刷新（标准库拿不到 TTL，不引入新依赖）。并发的解析请求合并为一次。解析失败不缓存，或最多缓存 5 秒。校验规则不变：解析结果里只要有一个受保护地址就整体拒绝。
   - **连接池**：每个规范化后的“主机:端口”一个共享连接池，只向缓存中通过校验的地址拨号，保留原域名用于 SNI 与证书校验。开启 keep-alive 与 HTTP/2。刷新后地址变化时，关闭指向旧地址的空闲连接。
   - **禁用名单**：每次请求仍先做 Base URL 规范化与禁用名单检查，新加入的禁用主机立即生效；`extra_blocked_hosts` 变化时清空全部连接池。
   - **超时**：超时全部来自请求的 context，不设客户端整体超时（ADR-0035 规则 5）。
8. **凭据明文缓存**（新增）：
   - 网关可以在进程内缓存解密后的渠道凭据，缓存键为渠道 ID 加密文的 key id 与 nonce。渠道更新凭据或换密钥时缓存自然失效，渠道删除时清除。
   - 明文不写日志，不进入任何响应；错误文本照旧先抹掉上游 Key。
9. **可见性**（沿用并更新用语）：
   - 渠道的 Base URL 与请求头规则只对所有者与管理员可见；模型详情里的公开渠道信息不含这些字段。
   - 上游授权校验的原始错误长度受限，只通过专用入口返回给所有者或管理员。

## 后果

### 正面影响

- 缺少密钥在启动时就暴露，备份恢复演练只需启动一次就能确认密钥环完整。
- 三类密文遵循同一套加密与校验规则，各自的边界都有明确记录。
- 网关请求省去每次的 DNS 查询与 TCP、TLS 握手，并能使用 HTTP/2。
- 以后要把密钥环换成 KMS、把拨号换成独立出站代理，不需要改领域契约。

### 负面影响与成本

- 启动时间随存量密文数量线性增加；当前规模可以忽略。
- 旧 key id 不能移除。某个密钥泄露后，只能停止用它做新写入，已有密文仍由它加密，彻底轮换要等重加密工具。
- 上游地址变化最多 60 秒后才生效。
- 渠道凭据明文常驻进程内存（维护者已接受）。
- 应用层防护不能替代基础设施级的出站 ACL；解析器与运行时网络仍属于运维信任边界。

### 风险与缓解措施

- **DNS 重绑定**：缓存只保存通过校验的地址；刷新得到的新地址重新校验，任一受保护地址就整体拒绝；已建立的连接仍指向原来校验过的地址。
- **新禁用主机仍可连接**：每次请求先检查禁用名单；设置变化时清空连接池。
- **遗失仍被引用的密钥**：启动即失败并指出记录。部署手册要求密钥环保留全部历史 key id，并与数据库备份一起管理。
- **内存转储泄露明文**：单实例、内网部署（ADR-0039）；能读取进程内存的人本来也能读取密钥环，信任边界相同。

### 验证

- 单元测试：URL 规范化、官方端点、受保护地址范围、DNS 混合答案、代理与重定向、钉住拨号、AEAD 绑定、DNS 缓存命中与连接复用计数、DNS 重绑定、修改禁用主机后清空连接池。
- 集成测试：缺失或损坏的密钥使启动校验失败，错误给出记录类型与 ID 且不含敏感内容；完整密钥环通过。
- 所有者、公开与管理员三类投影的字段隔离测试，继续沿用。
