# ADR-0037：首个管理员通过网页初始化

- 状态：已通过
- 日期：2026-10-11
- 决策者：维护者
- 关联内容：[ADR-0007](0007-adopt-invited-identity-and-server-sessions.md)、[Feature #49](https://github.com/NexusAgentX/Oh-My-AIHub/pull/49)、[SECURITY.md](../../SECURITY.md)

## 背景

ADR-0007 规定：初始管理员由一个只接受交互式密码输入的本地命令，在空系统中创建一次；不提供默认账号，也不提供环境变量明文密码入口。

2026-09-03（#49）起，实现改为 `/initialize` 网页：实例还没有管理员时，任何访问者都可以通过 `POST /api/instance/initialize` 提交用户名、显示名与密码，创建首个管理员并直接登录；此后该接口返回 409。当时没有新建 ADR。`SECURITY.md`、`PRODUCT.md` 与部署手册已按网页初始化描述，ADR-0007 的这一条一直未更新。2026-10-11 的 ADR 评审决定照现状记录。

## 候选方案

1. **本地交互式命令（ADR-0007）**：没有公开的初始化入口；但部署者必须进入服务器或容器执行命令，门槛高。
2. **公开网页初始化（现状，选定）**：部署后在浏览器完成，最简单。从服务对外可达到完成初始化之间，存在被他人抢先初始化的窗口。
3. **网页初始化 + 一次性令牌**：后端启动且没有管理员时生成令牌并打印到日志，提交初始化时必须带上，从而关闭抢注窗口；代价是部署者要去看日志。维护者决定暂不采用。

## 决定

采用方案 2。

- 实例中不存在任何管理员账户（含已停用的）时，`/initialize` 网页与 `POST /api/instance/initialize` 可用，任何访问者都可以提交。
- 创建在数据库事务内先加锁、再检查有没有管理员，所以并发提交只有一个成功，其余返回 409。实例一旦有管理员，接口永久返回 409。
- 密码由创建者自己设置，遵循普通密码规则，以 Argon2id 哈希保存，不回显。因为没有第三方经手，不要求首次登录改密；创建成功后直接建立会话。
- 创建写入审计。
- ADR-0007 的其他约束不变：不提供默认账号，不提供环境变量明文密码入口，其余账户只能由管理员创建并在首次登录时改密。

## 后果

- **收益**：部署者不需要登录服务器，部署后在浏览器一步完成初始化。
- **成本与风险**：存在抢注窗口——服务对外可达后、完成初始化前，任何能访问该地址的人都能抢先成为管理员。
- **缓解**：
  - 部署手册要求启动后立即访问 `/initialize` 完成初始化。
  - 如果发现管理员不是自己创建的，视为部署失败：停止服务，按故障处理手册排查。
  - 需要关闭这个窗口时，按方案 3 另立 ADR。
- **验证**：HTTP 测试覆盖首次初始化成功并建立会话、已初始化后返回 409；PostgreSQL 集成测试覆盖第二次初始化冲突。并发提交由事务内的锁保证只成功一次。
