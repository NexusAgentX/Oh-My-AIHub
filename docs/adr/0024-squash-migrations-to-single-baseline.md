# ADR-0024：数据库迁移压缩为单一基线

- 状态：已通过
- 日期：2026-10-08
- 决策者：项目维护者与 AI 产品团队
- 关联内容：Feature #165、[ADR-0006](0006-adopt-postgresql-goose-and-fixed-point-amounts.md)、[ADR-0017](0017-adopt-sqlc-domain-persistence-layering.md)、[ADR-0023](0023-remove-c2c-buy-orders.md)

## 背景

项目仍是未发布的中间态。迁移链 `0001`～`0010` 累积了不再有价值的历史：C2C 付款截图表 `c2c_evidence` 与渠道评分表 `channel_ratings` 建表后又被删除；为兼容历史买单保留了 `c2c_orders.side` 列、`NOT VALID` 约束以及买单专用的索引与校验分支；`0002` 为已存在的账户回填账本账户；还有按版本号迁移到中间状态才能运行的测试。

2026-10-08 维护者决定：生产数据直接删除重建，只保留账户与模型目录，不再保留对存量数据的兼容。因此逐版本迁移历史已失去用途，却会让每个读者都要重放十段历史才能知道当前结构，sqlc 也要解析全部历史。

## 决策目标

- 迁移目录只有一份可读、按领域分节的基线，直接描述当前产品事实。
- 基线结构与原 v10 等价，除明确删除只服务历史数据的遗留对象外，不改变任何行为、API、计价或账本不变量。
- 基线之后的结构变化沿用 ADR-0006 的追加式迁移，从 `0002` 起。

不处理生产数据的重建与导入（由后续发布 Feature 负责）。

## 候选方案

### 方案一：保留十个迁移

不改动，但保留的遗留列、约束和历史测试继续误导读者，并要求每个新读者理解已删除的功能。

### 方案二：压缩为单一基线并清理遗留结构

手写一份基线，以原 v10 的 `pg_dump --schema-only` 为对照，逐项证明差异只含有意删除的对象。

### 方案三：从 `pg_dump` 机械生成基线

对照最准确，但丢失注释、分组和可读性，且 dump 输出与 Goose 的语句边界不匹配。

## 决定

采用方案二。

1. `backend/internal/database/migrations/` 只保留 `0001_baseline.sql`，按“身份与目录、账本、渠道、API 网关、C2C、运维”分节并带中文注释；`Down` 删除全部对象。
2. 删除遗留结构：`c2c_orders.side` 及其默认值与约束、买单盘口索引、买单分支；`parent_hold_id` 改为 `NOT NULL`（卖单创建总是传入父持有）；校验函数与历史守卫函数只保留卖单语义；`c2c_evidence`、`channel_ratings` 不再创建。删除 `0002` 从既有账户回填用户账本账户的种子，系统账本账户 `platform_incentive`、`platform_loss` 与默认手续费率仍由基线写入。
3. 有意保留的结构：`api_calls.formula_version` 仍放行 `formula-v1` 与 `formula-v2`，因为网关结算路径仍识别两个版本；是否收敛由独立 Feature 评估。
4. 删除 `database.MigrateTo` 与依赖历史版本的测试（`c2c_sell_only_migration_test.go`、账本升级回填测试）；仍有价值的断言改写为只依赖当前基线。
5. 基线只对全新数据库有效。已有开发数据库须用 `docker compose down -v` 重建；不提供兼容层。
6. 本决定不改变 ADR-0023 的产品决策（C2C 只有卖单）；ADR-0023 中“迁移 `0009` 前置检查、保留 `side` 列与历史买单行”的实施机制随压缩不再适用。

## 后果

### 正面影响

- 当前数据库结构集中在一份文件中，新读者和 sqlc 不必解析十段历史。
- 数据库不再携带只服务历史行的列、约束和函数分支。
- 测试不再依赖按版本号迁移到中间状态。

### 负面影响与成本

- 既有开发数据库、含旧版本号的备份不再能直接迁移，需要重建。
- 迁移历史不可再按版本回溯；历史由 Git 保存。

### 风险与缓解措施

- 手写基线可能遗漏对象：以 v10 的 `pg_dump --schema-only` 与基线全新建库后的 dump 做差异，差异只允许包含上述有意删除项。
- 基线的 `Down` 是破坏性操作：仅用于空库与测试，运行手册已要求部署不执行 down。

## 验证方式

- 基线 dump 与 v10 dump 的差异只含第 2 条所列对象，记录于 PR。
- 空库上 `goose up`、`down`、`up` 均成功，`down` 后只剩 Goose 版本表且没有函数。
- Go 单元测试、PostgreSQL 集成测试、`mise run check-sqlc` 通过。

## 替代关系

无。部分补充 ADR-0006（迁移从基线之后追加）。
