# ADR-0015：MVP 完成后直接基于代码开发

- 状态：已通过
- 日期：2026-10-07
- 决策者：项目维护者
- 关联内容：Feature #94、ADR-0002、ADR-0003、ADR-0004

## 背景

维护者确认 MVP 已完成，明确要求清理 OpenPencil 及相关设计资产，后续无需先设计再开发。已有可运行界面和代码可以作为迭代基础，继续维护原型与实现两套状态会增加同步成本。

## 决策目标

取消独立设计阶段及工具前置依赖，让贡献者直接实现明确的需求。保留产品方向确认、Issue、独立 worktree、聚焦验证、PR 验收及真实用户结果验证。

## 候选方案

### 方案一：保留可选设计资产

可继续查看原型，但容易产生过时副本和残留约束，也不符合维护者要求清理的范围。

### 方案二：以当前代码为实现基线

删除设计资产和检查入口，通过实际界面与行为验证改动。历史原型仍可在 Git 历史中追溯，无需维持额外工具链。

## 决定

采用方案二。删除 DESIGN.md、design/、设计资产检查器和专用 Git 属性，移除 mise 与 CI 中的设计门禁。开发直接依据 PRODUCT.md、Issue 和现有代码进行，不要求 OpenPencil、独立设计阶段、可编辑设计源或预览。

前端沿用现有组件和样式，按影响验证实际交互、响应式及无障碍。产品范围和重大风险取舍仍由维护者确认。保留现有界面衍生内容对应的 MIT 许可于 `licenses/airtable-design-analysis-MIT.txt`；不改变业务运行行为，不卸载用户全局安装的工具或配置。

## 后果

### 正面影响

- 需求明确后即可直接开发，不再因设计工具不可用阻塞。
- 不再维护源稿、预览和实现之间的重复状态。

### 负面影响与成本

- 当前分支不再提供独立可编辑原型，历史原型需从 Git 历史读取。

### 风险与缓解措施

- 界面质量通过代码评审、聚焦测试和适用的浏览器现场验收保持；取消设计阶段不取消验收。
- 旧 ADR 保留历史结论并标记替代关系，当前指南与任务模板同步移除旧约束。

## 验证方式

检查当前指南、模板和配置不再要求设计资产；检查 mise 和 CI 保留原有非设计门禁；检查第三方许可保留、文档链接有效且业务源码不变。

## 替代关系

取代 ADR-0003 和 ADR-0004；取代 ADR-0002 中独立设计阶段、设计文件事实来源及资产同步要求，其余产品研发责任与验证规则继续适用。ADR-0001 已由 ADR-0004 取代，不重新生效。其他历史 ADR 和 CHANGELOG 中的原型、设计规范或资产验证记录仅为历史证据，不构成当前开发前置要求。
