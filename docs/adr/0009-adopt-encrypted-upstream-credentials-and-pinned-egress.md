# ADR-0009：采用版本化凭据加密与固定出站网络边界

- 状态：已通过
- 日期：2026-09-02
- 决策者：仓库维护者
- 关联内容：[Feature #19](https://github.com/NexusAgentX/Oh-My-AIHub/issues/19)、[Feature #20](https://github.com/NexusAgentX/Oh-My-AIHub/issues/20)、[ADR-0006](0006-adopt-postgresql-goose-and-fixed-point-amounts.md)

## 背景

平台需要代共享者保存上游 API Key，并在校验和后续代理请求中向用户提交的 Base URL 发起服务端请求。明文凭据或只依赖数据库访问控制无法覆盖备份泄露、只读查询和误回显风险；普通 HTTP 客户端又可能被私网域名、DNS rebinding、环境代理、重定向或特殊地址编码绕过，形成服务端请求伪造。渠道安全边界必须在 Feature #20 使用同一凭据和出站能力前固定下来。

## 决策目标

- 数据库、备份、通用 DTO 和日志都不能直接恢复或泄露上游明文凭据。
- 密钥能够轮换，且缺少旧密钥或密文损坏时系统必须失败关闭，而不是静默发布不可用渠道。
- 保存配置和每次真实访问都拒绝本机、私网、云元数据、保留地址与 OpenAI 官方端点。
- DNS 校验结果必须约束实际建立的连接，不能在校验和连接之间重新选择地址。
- 共享者可以保留必要的诊断信息，但公开市场和管理员治理不扩大敏感读取面。

本决策不定义平台 API Key、请求协议转换、流式回退、用量归一或结算状态机。

## 候选方案

### 方案一：数据库明文凭据与标准 HTTP 客户端

实现最少，但数据库读取、备份和误序列化会直接暴露全部 Key，标准客户端还会自动使用代理、连接池和重定向，无法证明实际访问目标经过同一安全判断。

### 方案二：应用层版本化 AEAD 加密与每次解析后固定地址

应用使用外部注入的版本化密钥环加密凭据；保存和访问都验证 DNS，实际连接固定到本次解析通过的地址，同时保留原域名用于 TLS 校验。重定向、环境代理和连接复用全部禁用。

### 方案三：托管 KMS、网络代理与独立出站沙箱

密钥隔离和网络防护更强，但首版单实例尚无已选定的云平台或出站基础设施，引入托管服务会提前绑定部署方案。以后可以在保持当前领域契约的前提下替换密钥与拨号实现。

## 决定

采用方案二。

- 上游凭据使用 AES-256-GCM 加密；每次写入生成随机 nonce，附加认证数据包含渠道 ID、凭据版本和密钥 ID。数据库保存版本、密钥 ID、nonce 与密文，不保存或回显明文。
- 密钥环从运行环境注入，格式为多个 `key-id=base64-key`；活动密钥用于新写入，旧密钥在全部对应密文完成重加密前必须保留。服务启动时逐一解密全部存活渠道凭据，任一失败即拒绝启动。多副本轮换必须先把完整新旧密钥环和同一个新活动密钥 ID 部署到全部副本，确认旧配置副本退出后再执行重加密；只有库存和全部副本都不再引用旧密钥时才能移除旧密钥。无法保证这一顺序时暂停凭据写入与轮换。
- Base URL 只允许 HTTPS 域名、允许端口和不含具体 API 资源名的根前缀；拒绝用户信息、查询、片段、IP 字面量、路径穿越、编码分隔符和永久禁用的 `api.openai.com` 及其子域。
- 保存和每次访问都在受限上下文中解析全部 DNS 候选；任一候选属于本机、私有、链路本地、组播、未指定、保留、文档、NAT64、6to4、Teredo 或未由 IANA 分配的 IPv6 全局单播范围时整次拒绝。实际拨号固定使用本次验证后的地址，目标端口和原始主机必须完全匹配，TLS 继续验证原始域名。
- 出站客户端不使用环境代理、不跟随重定向、不复用连接，限制 TLS、响应头、总时长和校验响应体。默认只允许 443，配置只能显式追加端口或禁用域名，不能解除永久禁用项。
- 所有者接口可以读取完整 Base URL、上游模型 ID 和授权校验历史；公开市场和管理员接口使用独立非敏感投影。路由内部租约的 Base URL、上游模型 ID 和凭据字段禁止 JSON 序列化。

## 后果

### 正面影响

- 数据库和普通 API 投影不再直接暴露上游 Key，密文复制到其他渠道或版本也无法通过认证。
- 保存、校验与后续路由使用同一出站策略，DNS 判断与实际连接目标之间具有可验证的绑定。
- 密钥丢失和密文损坏会在启动或单报价解析时明确暴露；单个不可解密报价不会阻断池内其他候选回退。
- 未来可将密钥环替换为 KMS、将拨号替换为独立出站代理，而不改变渠道、报价和路由租约的领域契约。

### 负面影响与成本

- 部署者必须把密钥环与数据库备份作为一个恢复集合管理；遗失仍被引用的密钥会使服务拒绝启动。
- 每次访问重新解析且禁用连接复用，会增加 DNS、TLS 和建连开销；首版优先安全和可解释性，性能基线留给真实试用测量。
- 应用层防护不能替代基础设施级出站 ACL；错误配置、解析器或运行时网络仍属于运维信任边界。

### 风险与缓解措施

- **轮换时提前删除旧密钥或混用活动密钥 ID**：全部副本先部署完整新旧密钥环并统一切换新活动密钥 ID，确认旧配置副本退出后再重加密；库存和全部副本都不再引用旧密钥后才能移除，否则暂停写入和轮换。
- **DNS rebinding 或混合公私网答案**：每次重新解析，任一危险候选使整次请求失败，实际连接固定到通过校验的地址。
- **重定向或环境代理绕过**：客户端明确禁用两者，并禁止复用可能指向旧地址的连接。
- **诊断数据扩大泄露面**：原始错误长度受限且只向授权所有者或管理员的专用历史入口返回，通用、市场和路由 DTO 不含敏感字段。

## 验证方式

- 单元测试覆盖 URL 规范化、官方端点、私网与转换/隧道地址、DNS 混合答案、代理、重定向、固定拨号、协议端点和凭据 AEAD 绑定。
- PostgreSQL 集成测试覆盖密文库存、缺失或损坏密钥失败、重加密、撤销、逻辑删除、发布校验门禁和路由资格降级。
- HTTP 测试覆盖所有者、公开市场与管理员投影字段隔离，以及原始错误只通过授权历史接口返回。
- Compose 与本地启动必须显式提供活动密钥和密钥环；`SECURITY.md`、`README.md` 与恢复流程保持一致。
