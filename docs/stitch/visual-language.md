# 两端共享的贴纸视觉语言

这是需要保留的品牌，不是旧界面布局要求。以「芥末与墨的贴纸风」建立整套新结构，不照搬现有页面。这里约束视觉材料、品牌和含义；布局与具体交互由本端设计任务决定。

## 纸、墨线与贴纸

- 整个应用在一张暖色点阵纸上，点阵低对比、约 20px 间距。导航、工具区与内容沿用同一纸面，不靠多种背景板切碎页面。
- 卡片 / 主要表面像贴纸：2px 墨线、圆角、向右下偏移且不模糊的硬投影。常用投影为 2 / 3 / 4 / 6px 四级；手机可减轻一档。
- 按钮、徽标和分段选择有胶囊特征；输入框圆角较小。典型卡片圆角 14px、输入框 10px 是品牌基线，不要求锁死整个应用的空间密度。
- 只保留一层贴纸结构。卡片内部的列表、分组、明细与表格用细分隔线，不逐行描粗边或加硬投影。高密度工作区允许一个整片工作表面，不把每个字段包成卡片。
- 应用内表面端正、对齐。倾斜只可保留在公开介绍的 “AIHub” 品牌标签，不让表格、表单、标题栏和弹层歪斜。
- 不使用渐变、毛玻璃、发光、模糊投影。不要将品牌改成通用紫蓝 AI SaaS、纯黑终端、儿童玩具或到处散落的便签。

## 色彩与状态

| 语义 | 使用方式 |
| --- | --- |
| 纸面 / 贴纸表面 | `--paper` / `--canvas`，点阵 `--paper-dot`；表头和只读区域可用 `--sunken` |
| 墨与正文 | `--ink` 标题、`--body` 正文、`--muted` 辅助；内部细线用 `--hairline` |
| 主色 | `--mustard` 芥末，用于主操作、选中项与标志性余额；纸面链接 / 焦点使用 `--mustard-text` |
| 正常 / 成功 / 收入 | `--mint` 色块，或普通表面上的 `--positive` 文字 |
| 信息 / 进行中 | `--sky` 色块，或 `--info` 文字 |
| 待处理 / 警告 | `--mustard` 色块，或 `--warning` 文字 |
| 失败 / 危险 / 支出 | `--rose` 色块，或 `--danger` 文字 |
| 中性 / 停用 / 未知 | 中性表面、细边与文字；未知不是失败，也不是数值 0 |

每个当前交互上下文只突出一个芥末主操作：弹层打开时它承接当前主操作，后方工作区不争抢。选中导航和余额仍可使用芥末，但不能让满屏色块都像可点击主按钮。糖果色只表达数据或状态，不用来随意区分业务栏目。

色块上的文字统一用 `--on-color`，不可放低对比的辅助文字。金额保留正负符号；状态同时有文字 / 图形，不只靠颜色。图表未知值保留缺口，图例、单位、范围和样本量清楚，不用无含义的彩虹色。

导出文件末尾附从现有 `tokens.css` 读取的浅色 / 墨夜色值，供 Stitch 直接取色；这些是品牌基线。新增组合需核对对比度，不能假定沿用某一颜色就使所有组合合格。

## 浅色与墨夜

两套主题同等完整，默认跟随系统，可手选浅色 / 深色，偏好只在本设备保存。切换入口的位置由新设计决定。

浅色是暖纸与深墨；深色是暖调墨夜、浅墨线、近黑硬投影、降低亮度的芥末和糖果色，不是纯黑配刺眼纯白。表格、表单、图表、代码、弹层、加载、错误与 PWA 外壳都要覆盖。主题启动时避免白屏闪烁；这是一项设计目标，不用在页面铺技术解释。

## 字体、密度与信息层级

- 标题、品牌和关键数字：Baloo 2（拉丁与数字）+ 源泉圆体 GenSenMaruGothic TW（中文），粗字重约 800；正文 / 表单 / 表格使用系统字体；Key、模型 ID、接口地址、请求 ID 与代码用等宽字体。
- 数字等宽、表格金额右对齐、单位在相关数字旁。大数字突出当前任务，不让所有统计卡都巨大。
- 以 4px 为间距基线。标题层级靠字号和空间建立，不给每段文字加色或粗体。
- 长模型 ID、长 Key 名、中文与英文混排必须可识别、可展开 / 复制；长文本不能把尾部操作挤走。用于辨认的 ID 不任意截掉区分部分。
- 各端可以采用不同密度。移动输入文字至少 16px；桌面长时间阅读优先可读性，不能以 11px 密集小字解决复杂度。
- 留白帮助分组，不用大片空卡撑高度。论坛正文可阅读，数据页可扫描，不强行使用同一种卡片节奏。

## 组件与反馈

- 主按钮为芥末胶囊、墨线与硬投影；次按钮为中性贴纸；低权重操作可无边框 / 投影；危险操作用粉色语义。可点击贴纸按下轻移到投影位置，投影收起；不可点击卡片无按压暗示。
- 提供默认、悬停、按下、键盘聚焦、禁用、加载与错误状态。触屏功能不能依赖悬停；禁用操作有可获得的原因。
- 输入框保留可见标签，错误紧邻字段。placeholder 不是唯一标签；继承值显示有效默认与来源，不能误当已填写覆盖值。
- 信息多时渐进披露；高级设置在当前表单内折叠并标出已改项数。主任务不强迫理解“路由池、协议池、冻结、预授权”等内部术语。
- 复制紧邻对应值，成功反馈短暂且明确；错误持续到可处理。长任务显示状态、已完成部分和允许的下一步，不用无限转圈代替过程。
- 重要详情在本端合适的表面呈现；不强制桌面右抽屉或手机底部抽屉。需要完整阅读、长表单或多步核对时，给予足够空间。
- 浮层有标题、关闭 / 返回和明确主动作；打开后焦点进入，关闭后回到触发处。避免多层弹层堆叠。

## 标志、吉祥物与素材

- 标志是芥末圆角方形卷角贴纸，中间墨色 O，硬投影；品牌文字为 “Oh-My-AIHub”。不要重新发明名称或标志。
- 吉祥物为惊讶脸“哦！”与芥末滴。惊讶脸用于空状态、404、失败；芥末滴用于欢迎、完成与轻量加载。每屏最多一个主要吉祥物，避免在表格、表单、确认正文里卖萌。
- 启动图标保留卷角贴纸的识别，避免关键轮廓落入系统裁切区。原生状态栏 / 窗口控件是系统区域，画板可标注，不在产品中伪造可点击的系统按钮。
- 不需要装饰性摄影。已有品牌资源和自托管字体优先；外部图标 / 字体 / 图片需保留来源和许可。供应商图标不冒充平台品牌。
- 字体 [Baloo 2](https://github.com/EkType/Baloo2) 与[源泉圆体](https://github.com/ButTaiwan/gensen-font) 使用 SIL OFL 1.1。风格受 [codex-resets.com](https://codex-resets.com/) 启发，只保留纸面、墨线、硬投影和胶囊语言，不复制其代码、标志与特色组件。

## 人体工学与无障碍底线

- 主要任务的操作靠近所影响的内容，位置稳定；筛选、详情、返回保持上下文，避免为了比较两项反复进出页面。
- 移动触控目标至少 44×44 CSS px；破坏性动作与常用动作留足间隔。桌面也不能让图标命中区小到难点。44px 是本项目采用的设计目标，对应 WCAG 2.5.5 增强项，不能称为所有 WCAG AA 控件的法定最小值。
- 正文对比至少 4.5:1，大字和必要非文本信息至少 3:1；焦点清楚。数字和颜色都不能成为理解状态的唯一线索。
- 完整键盘路径、合理顺序、语义标签、屏幕阅读器可理解的状态与操作；可排序项目有非拖动操作；所有关键任务不依赖手势或长按。
- 吸顶栏、底栏、键盘与弹层不挡当前字段、焦点和主要操作；支持文本放大，不以禁止缩放解决布局。
- 减少动态效果时取消弹跳 / 位移动画；正常模式也不持续晃动业务数据。动效只解释状态和层级，不延迟操作。

这些要求的依据是 [W3C 触控目标增强项](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)、[焦点不被遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)及 [web.dev PWA 应用设计](https://web.dev/learn/pwa/app-design)。具体任务频率、导航点击目标和两端分工属于本次设计假设，不声称已做用户实验。
