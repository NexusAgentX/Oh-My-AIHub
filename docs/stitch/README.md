# Google Stitch 设计交接

本目录是 2026-10-20、`fae12fb` 功能基线的原型设计交接快照，不是第二份持续维护的产品规则。功能变化后需先核对当前实现再更新快照；`PRODUCT.md`、`DESIGN.md` 和设计 token 仍各自维护原有事实。

本次仅提供设计输入，不修改线上界面，不实施 PWA，也不预先确定新页面数或信息架构。旧导航与布局仅代表现有实现，不约束本次原型。

## 文件与用途

| 源文件 | 内容 |
| --- | --- |
| [product-spec.md](product-spec.md) | 成员 F01–F23 与管理员 A01–A12 能力、字段 / 状态 / 权限、关键旅程与非目标 |
| [visual-language.md](visual-language.md) | 保留的贴纸品牌与两端共享的视觉、无障碍边界 |
| [desktop.md](desktop.md) | 独立桌面应用、键盘与比较效率、窗口与 PWA 状态 |
| [mobile.md](mobile.md) | 独立移动应用、单手与触屏任务、移动 PWA 生命周期 |

功能只在产品规格中写一份，共享视觉只写一份；导出时再组合，避免两端拷贝后互相漂移。配色从 `frontend/src/styles/tokens.css` 读取，不在本目录另设色值事实来源。各端交互目标是本次设计要求，不表示当前产品已实现。

## 导出可直接上传的文件

在仓库根目录运行（Python 3.9 或更新版本，只使用标准库）：

```sh
python3 scripts/export-stitch-briefs.py --output /tmp/oh-my-aihub-stitch
```

输出目录与同名 `.zip` 必须尚不存在，脚本不会覆盖已有文件。导出得到：

```text
oh-my-aihub-stitch/
  README.md
  product-spec.md
  desktop/design.md
  mobile/design.md
oh-my-aihub-stitch.zip
```

两份 `design.md` **均自包含**：本端任务 + 共享视觉 + 完整产品功能规格 + 从 token 生成的浅 / 深配色表。即使 Stitch 只上传一个文件，也不缺功能或风格上下文。单独的产品规格供人阅读、核对或另行使用，不要求重复上传。

不上传真实凭据、收款信息或成员数据。仓库既有截图可辅助理解品牌，但可能来自旧功能版本，不应作为本次页面组织或功能的事实来源。

## 在两个独立项目中使用

桌面项目上传 `desktop/design.md`，随后粘贴：

> 请按上传的 design.md 为 Oh-My-AIHub 重设计完整桌面应用。保留芥末与墨的贴纸风，页面数量、组织、导航和布局全部可重做。先提出适合桌面及安装后独立窗口的信息架构、完整屏幕目录与功能覆盖表，然后按目录逐批生成所有原型，覆盖全部成员与管理功能、浅色与墨夜、关键交互状态。不要沿旧网站换皮，也不要只画首页。

移动项目上传 `mobile/design.md`，随后粘贴：

> 请按上传的 design.md 独立设计 Oh-My-AIHub 移动 PWA，使其像原生手机应用。保留贴纸风，重新决定首页、导航、页面和任务流，不沿用桌面版结构或旧移动网站。先给出信息架构、完整屏幕目录与功能覆盖表，再逐批生成全部成员与管理原型，覆盖单手触达、键盘安全区、站外付款返回、浅色与墨夜，以及 PWA 弱网和恢复状态。不能以手机端为由删功能或只给窄屏网页。

后续要求每个功能 ID 对应可见入口、具体屏幕、操作、返回与状态；一个 ID 不要求恰好一个页面，多个页面也可以共同完成一个能力。覆盖表与连续旅程用于约束完整性，不冻结 Stitch 的页面方案。

## 规则优先级与事实核对

- 用户本次明确的独立双端重设计方向，优先于旧页面组织与旧响应式规则。
- 产品能力与权限按已核对代码及功能规格；贴纸品牌保留，具体界面结构可重做。
- 不把原型中的 PWA 目标说成当前已有功能；新增缓存、隐私、后台能力或产品范围决策继续标为待确认。
- 本地交接检查：源文档与源码对应、功能 ID 完整、导出内容与源文档一致、链接有效、浅 / 深配色来自 token，运行 `git diff --check`。不因文档交接宣称界面验收、CI 或部署已通过。
