# Google Stitch 设计任务：桌面应用

请为 Oh-My-AIHub 从零重构桌面端信息架构和全站原型。目标是适合长时间工作的桌面应用，包括通过 PWA 安装后的独立窗口体验。后附产品规格与共享视觉语言是完整输入，不需要访问现有网站才能开始。

**优先级：业务和权限正确 → 全功能有入口 → 操作省力与上下文稳定 → 保留贴纸风 → 视觉精修。** 本项目只设计桌面，不生成移动页面的放大版，也不沿用现有网站的页面清单。

## 可以完全重做什么

页面数量、首页、导航、栏目、工作区划分、详情承载、列表密度、多栏布局、工具栏、编辑流程均可重做。品牌纸面、墨线、芥末与贴纸规则保留；现有侧栏宽度、顶栏结构、卡片堆叠和全站最大内容宽度不构成约束。

不要先画旧侧栏再把内容换皮。先从接入 / 观察、发现 / 选择、共享 / 经营、积分 / 交易、交流 / 求助、治理任务之间的关系提出本端组织，再决定用几种工作区、页面与面板。

可把稳定的导航区域、上下文工具区、主工作面和按需详情区作为探索方向；这是方向提示，不是必须采用的四块布局。一个工作区可覆盖多项功能，一项任务也可拆成多个阶段。

## 桌面人体工学

1. **看得见方向**：当前位置、当前对象和管理 / 成员上下文明确；页面标题不在多处重复。导航和返回不依赖浏览器工具栏，也不能只能靠快捷键找到。
2. **少往返比较**：模型报价、候选渠道、调用与账单、贡献差异与报告适合在同一视野对照。可用列表 + 详情、分栏或可展开区域；不要把长信息硬塞进窄抽屉。
3. **保持工作上下文**：筛选、排序、分页、所选对象、滚动位置和未保存表单有清楚恢复行为。从详情到配置再返回不用重找原对象。列表实时更新不抢焦点、不将正在查看的行推走。
4. **高密度但可扫描**：充分利用横向空间，保留关键字段与行操作；统计按任务显示，不用一屏大数字卡挤走工作内容。金额对齐、单位可见、列宽稳定，信息优先级胜于卡片数量。
5. **操作靠近对象**：筛选与结果、编辑与保存、选项与生效来源靠近。长编辑器可固定提交区，但不盖住最后字段。单个目标主操作突出，危险操作与日常操作错开。
6. **键盘完整**：Tab / Shift+Tab 可完成任务，焦点清楚；Esc 关闭非阻塞浮层，有未保存内容时先处理离开。输入中的 Enter 不触发意外删除、放行或仲裁。
7. **快捷方式只是加速**：可探索可发现的命令导航 / 快捷键入口，映射已有功能；不虚构全站业务搜索或后台 API。快捷键不覆盖输入编辑或系统快捷键，鼠标也能完成全部任务。
8. **少做无效确认**：复制、筛选、切换视图直接反馈；删除、Key 停用影响、放行、调账与仲裁按真实风险设计确认。确认中保留关键对象与金额，不只写“确定吗”。

建议以“熟悉产品后，从稳定导航到接入复制、最近调用、我的渠道、待处理交易通常 1–2 次导航操作”为设计目标，计数不含输入与必要的资金核对步骤；功能复杂度不能靠隐藏来满足次数。最终方案需要解释未达到目标的原因。

## 桌面 PWA 目标体验

- **独立窗口可自洽**：无地址栏和浏览器返回键时仍可返回、刷新当前数据、进入顶层区域、识别当前账户与退出；从深链接启动有完整导航，不把用户困在某个详情。
- **像桌面工具**：窗口标题表达当前工作区 / 对象与产品名；窗口缩放和并排使用时仍能工作。考虑 1440×900 主画板、1280×800 常见窗口、1024×768 紧凑窗口，以及约 800px 宽并排窗口。
- **紧凑桌面仍是桌面**：可以收起次要导航、按需展开详情、降低可见列；不因窗口变窄就机械套手机底栏。长表格优先收列或打开字段面板，若保留局部横向滚动需有明确范围，不能让整个应用横向漂移。
- **尊重系统窗口**：默认独立窗口；系统控制区与拖动区保留空间。不假设所有平台支持 Window Controls Overlay；可画支持时的增强方案，并同时给普通标题栏回退，不能把关键按钮放在可能被系统遮住的位置。
- **浏览器 / 已安装状态**：浏览器内合适位置可提供安装入口或说明；安装后移除重复邀请。平台不支持程序化安装时说明系统途径，不绘制无效安装按钮，不在首次打开时强迫安装。
- **离线与恢复**：可以保留无敏感内容的应用外壳和清楚的离线页；余额、交易状态、收款方式、Key 和私密内容不得以陈旧缓存冒充当前事实。写操作不可用时保留本次输入上下文并解释原因，不排队执行资金 / 治理操作。
- **提交途中断线**：结果待确认，恢复后查询服务端状态。不能用“离线成功”或自动重复扣账 / 放行补偿体验。
- **应用更新**：更新可用时非阻断提示；编辑或资金核对中不强制刷新。用户选择更新前处理未保存内容，更新后尽量回到原上下文。是否持久缓存敏感草稿待实现评审确认。
- **外部链接与多窗口**：官网 / 文档等外部目标可识别，返回应用不丢当前任务；浏览器开新标签与多窗口查看时权限相同，各窗口结果变化以服务端事实为准，不假定跨窗口已自动同步。

上述 PWA 项是设计目标。不得声称当前已有安装、离线缓存、后台同步、推送或跨设备恢复能力。

## 本端应重点探索的工作方式

| 任务 | 设计需解决的问题；不限定页面形态 |
| --- | --- |
| 接入与 Key | 高频复制直接可达，默认遮蔽；高级模型限制 / 路由覆盖与当前 Key 的关系可理解 |
| 模型与候选比较 | 同筛选下比较报价、单位、证据与五种调用方式，配置时不丢对照依据 |
| 调用分析 | 从指标 → 样本 → 尝试 / 费用 / 链路 → 关联配置形成清楚的下钻与返回路径 |
| 共享渠道经营 | 运行概览与异常优先，查看记录不丢编辑；模型折扣、入口顺序与继承来源清楚 |
| 贡献与审核 | 大量字段、差异、影响、检测报告可并排核对；待发布与发布成功严格区分 |
| 积分与 C2C | 资产、账单、市场、我的卖单和交易彼此关联；人民币与积分方向不混淆 |
| 论坛与工单 | 阅读 / 编辑空间充足，长文编辑不挤在狭窄浮层；私密范围始终可辨 |
| 治理 | 待处理 → 对象 → 处置 → 结果形成工作流；账本全局、交易分录与审计能相互定位 |

## 要交付给我的桌面原型

1. 完整信息架构、屏幕 / 面板目录与导航关系；不预设页面数。说明主要任务的入口和怎样回到原上下文。
2. 产品规格全部 F01–F23、A01–A12 的覆盖表；每个落点有对应原型，包含管理员和社区治理。不能只给一张通用管理表格代表全部管理能力。
3. 第 6 节全部关键旅程的连续原型与交互说明；高级表单、交易、检测、审核与诊断需要各自关键状态。
4. 完整浅色 / 墨夜设计系统，并给代表性的模型比较、调用详情、渠道编辑、交易和管理场景两套主题原型，其余页面也有明确可套用的主题定义。
5. 主窗口、紧凑窗口和并排窗口的组织变化；至少在复杂工作区展示密度变化、键盘焦点与长内容处理。
6. 独立窗口启动 / 深链接、安装入口、离线 / 恢复、结果待确认和更新提示的原型。系统区域标注即可，不把系统控件当作站内功能。

先给出有理由的本端方案，然后按完整目录逐批生成全部原型。不要只写设计建议，不要把本任务缩成首页美化，也不要输出移动端自适应作为本项目的设计结果。
