# Google Stitch 设计任务：移动原生应用体验

请为 Oh-My-AIHub 独立重构移动端全站原型，以安装在主屏幕后日常使用的 PWA 为主要情境。它应像一款为手机设计的应用，有稳定方向、清楚层级、顺手操作和恢复能力。后附产品规格与共享视觉语言是完整输入。

**优先级：业务和权限正确 → 全功能有入口 → 单手操作与任务连续 → 保留贴纸风 → 视觉精修。** 本项目不继承桌面版的页面划分，也不把桌面表格、侧栏或多栏工作区压成一根长列。

## 允许独立设计的范围

移动首页、页面数量、顶层目的地、导航层级、详情、编辑与核对流程都可独立于桌面版。两端只需保持业务、权限、核心名词、金额与状态含义一致；不要求同页同路径同布局。

依据手机的使用情境重新组织：快速复制接入信息、查异常和余额、处理待付款 / 待放行交易、查看或调整自己渠道、提交工单，以及完成必要的管理任务。频率是设计假设，不是实际统计，不能据此删除较少使用的能力。

可探索少量稳定的顶层目的地和各自独立的返回栈、就近的情境操作与全屏任务；顶层通常以 3–5 项便于理解，但数量和名称由方案论证，不照搬旧“首页 / 模型 / 渠道 / 积分 / 我的”。不能把所有工作都藏进“我的”，也不能用一个“更多”占位代替真实入口。

## 移动人体工学

1. **单手好够到**：高频导航、主要提交和当前任务动作优先在舒适触达区；较危险操作远离常用返回 / 关闭按钮，不把所有动作挤到右上角。双手和左手使用同样可行。
2. **触控可靠**：命中区至少 44×44 CSS px，主要操作可更大；图标的可见大小不等于命中区大小。相邻危险操作留间隔，不让复制、删除和展开挤在一行小图标中。
3. **每步目标清楚**：复杂选择、长表单、长文和审核优先给完整任务空间；短筛选 / 简短选择可用底部面板。不要在半屏面板里塞大量字段或再叠第二层面板。
4. **有原生式层级**：顶层入口稳定；详情有标题和明确返回；编辑有返回 / 取消、提交与未保存保护。返回先结束当前临时层，再回来源，不直接跳首页或退出应用。
5. **不靠隐蔽手势**：滑动、拖动、长按仅能加速；必须有可见等价操作。手机候选排序也要上移 / 下移等替代，不依赖精细拖动。
6. **阅读与操作分开考虑**：列表先露出决定下一步需要的信息，完整字段进入详情 / 展开；不把桌面每行变成十几个标签的高卡片。列表摘要不能牺牲价格单位、状态或关键对象识别。
7. **滚动位置可预测**：返回恢复筛选和位置；切换顶层目的地回到该区域上下文。进行中的编辑先处理未保存内容；实时刷新不抢视线，不把当前条目推走。
8. **输入顺手**：输入文字至少 16px，金额 / 数量用合适键盘，登录和密码支持系统填充；中文输入法组合中不意外提交。键盘出现后不挡当前字段、校验提示或提交操作，不用三个固定栏抢剩余空间。
9. **逐步披露复杂度**：高级设置仍在同一编辑上下文内折叠并标已改项，不能只显示省略字段的“简化版”。必要的长任务可分步骤，但要保留整体进度、回改和同一份草稿。
10. **触屏反馈就地可见**：复制、保存、加载与错误不藏在手指或键盘下面；禁用按钮的原因可读。常规动作不反复弹确认，放行和仲裁等展示确切对象、金额与后果。

建议把查余额、复制接入、查最近调用和处理待办设计为从顶层稳定入口通常 1–2 次导航操作可达；不含输入 / 核对步骤。这是设计目标，不能以删除步骤中的真实业务校验或遮蔽功能换取达标。

## 移动 PWA 目标体验

- **主屏幕启动**：启动标志、纸色背景与浅 / 深主题衔接；已有会话进入合适的工作上下文，未登录进入登录，不每次重看落地页。启动、会话检查与业务加载有所区分。
- **没有浏览器栏也能用**：应用内返回、顶层导航、复制和账户操作齐全；从交易 / 调用 / 工单深链接进入时有合理上级，无历史栈也能离开详情。
- **系统返回协调**：Android 返回按当前层级关闭临时层 / 返回来源；iOS 有清楚可触达的返回操作，不要求依赖系统手势。浏览器模式仍使用正常历史，不以截获返回把用户困在应用。
- **安全区和屏幕变化**：适配刘海、状态栏、手势区、动态地址栏、横竖屏及分屏。主要内容与按钮不落入遮挡区；底部操作和导航不重复占用两条大栏，内容最后一行可滚到可见位置。
- **安装指导按环境出现**：支持安装时可轻量邀请；iOS 等需要系统步骤时给真实说明，已安装后不再提醒。可跳过，不用强制引导阻碍处理交易。
- **外部应用返回**：付款本来就在站外。用户切到支付应用 / 浏览器再回 PWA 后仍在原交易，恢复时刷新服务端状态和倒计时；不据离开应用时间推断已付款，不根据本地时钟宣告交易最终取消。
- **挂起与恢复**：后台回来时验证当前状态，Key / 账户停用或交易被另一端更新时显示事实；进行中的检测从服务端状态继续展示，不依赖前台计时器永久运行。
- **离线 / 弱网 / 提交中断**：离线可进入无敏感内容的外壳与重试；资金、放行、仲裁、调账等不在离线队列等待自动执行。余额与交易不把陈旧缓存呈现为已确认；提交中断标结果待确认，恢复后查询，不能盲目重复发起。
- **本地恢复有边界**：导航和非敏感筛选可记住；凭据、收款账号、IP、论坛 / 工单私密正文和跨设备草稿不默认为离线可读。编辑内容保存 / 恢复策略需明确，不能把某次页面内保留说成永不丢稿。
- **更新不打断任务**：更新提示可延后，交易确认或编辑时不强刷；用户处理未保存内容后再更新，恢复合理上下文。
- **刷新与通知**：列表可探索下拉刷新，但编辑和资金核对避免误触重载，并提供可见刷新替代。不依赖推送通知或系统后台常驻完成任务；现有待办可在应用内突出，不新增通知已读体系。

这些均是原型设计目标，不表示当前代码已实现安装、离线、推送、后台同步或系统级能力。不要把 iOS / Android 系统状态栏、权限弹框或安装弹框画成能由应用任意控制的控件。

## 本端复杂任务必须另作设计

| 能力 | 手机需要解决的问题；不限定页面数 |
| --- | --- |
| 模型筛选 / 比较 | 筛选面板显示已选与结果语境，应用 / 清除可见；多报价用可阅读的比较或逐项详情，别用超宽表格缩小字体 |
| 调用与链路 | 列表摘要先服务定位；尝试、费用、图表、地图 / 回放有独立阅读空间；长时间线无需精细手指定位也能查看 |
| Key / 渠道高级编辑 | 键盘避让、保存可达、明确继承 / 覆盖；长模型清单可检索、只看已选，原表单上下文保留 |
| 贡献 / 检测 / 审核 | 字段与证据可分层阅读，返回保留草稿；看报告后能回原审核对象，完整差异与影响不能因手机而被省略 |
| 积分交易 | 买卖身份、站外金额、倒计时、当前状态和下一步清楚；卖家放行要核实到账；外部付款后返回仍有连续体验 |
| 论坛 / 工单 | 阅读和全屏编辑顺手，Markdown / 预览、图片与附件工具可用；键盘不能挤掉发送 / 保存，私密范围可见 |
| 管理员 | 有可见管理入口、明确管理模式、返回成员空间；账户、审核、仲裁、账本、设置、社区管理都可完成，不用“电脑端可用”占位 |

## 要交付给我的移动原型

1. 独立信息架构、顶层导航、各区域返回关系、全部屏幕 / 全屏流程 / 面板目录；不以桌面页面数为输入。
2. 产品规格 F01–F23、A01–A12 完整覆盖表；每一项有可见入口与实际原型，包含高级设置和所有管理功能。
3. 第 6 节全部用户旅程；尤其给出买家付款 → 切到外部应用 → 返回刷新 → 标记付款 → 卖家确认，以及已付款申诉与管理员仲裁的连续状态。
4. 以 390×844 为主画板，在 360px 和 430px 宽检查关键屏幕；另给键盘展开、文本放大、横屏 / 短屏、安全区的复杂表单与交易状态，不只导出三张缩放截图。
5. 浅色 / 墨夜系统与代表性的列表、模型详情、Key / 渠道编辑、进行中交易、工单和管理操作双主题原型。
6. 主屏幕启动、深链接无历史栈、安装指导、弱网 / 离线、结果待确认、挂起恢复和可延后更新的状态设计。

先说明这套组织怎样让手机更顺手，再按完整目录逐批生成全部原型。请真正设计手机应用的任务流，不交付一组窄屏网页，也不要因为功能复杂而删掉入口。
