# Oh-My-AIHub 产品功能规格

> 用途：给 Google Stitch 的重设计输入。功能核对基线为 2026-10-20 的 `main`（`fae12fb`）。这是该版本的设计交接快照，持续产品规则仍以仓库 `PRODUCT.md` 为准。

## 1. 设计任务与自由度

重新设计整个产品的原型，以更少的理解、寻找、移动和重复操作完成任务为目标。保留业务能力、权限与贴纸品牌；页面数量、页面边界、信息架构、布局、导航、首页、详情展示方式和操作流程均可重做。

本规格按能力组织，**能力不等于页面**。允许合并、拆分、增加或删除页面，允许把旧页面变成工作区、详情面板、全屏任务流或就地操作；删除页面必须把它承载的全部能力迁到明确可访问的位置。不要以现有路由、侧栏分组或截图布局为新设计的骨架。

桌面端与移动端是两个独立 Stitch 项目，可以有完全不同的首页、导航和任务结构。两端覆盖相同的适用功能与权限；不能把“请到电脑操作”作为移动端高级功能的唯一出口。两端保持核心名词、金额语义、状态含义和品牌一致。

本次交付是原型与交互规格，不改动实际网站，也不代表 PWA 已实现。新设计方向取代交接材料中旧布局的约束；现有侧栏、底栏、断点、首页顺序和抽屉形态均不是必须保留的条件。

## 2. 产品、成员与任务

Oh-My-AIHub 是受邀小圈子使用的 API 共享市场与积分 C2C 市场。成员把自己已有的上游 API 渠道共享给其他成员，平台提供统一接入、自动选择渠道、故障回退、调用观测和积分结算。

| 身份 / 使用情境 | 要完成的任务 | 权限边界 |
| --- | --- | --- |
| 访客 | 理解产品、登录；未初始化实例创建首个管理员 | 不浏览成员市场、论坛、账单 |
| 成员使用 API | 复制接入配置、选模型、管理 API Key、查调用与花费 | 本人 Key、调用与账单 |
| 同一成员共享渠道 | 添加渠道、调折扣、看收入和异常、贡献目录资料 | 本人渠道的经营与受限调用视图 |
| 同一成员买卖积分 | 买积分、发布卖单、付款、放行、申诉 | 本人交易和收款资料 |
| 同一成员交流 / 求助 | 论坛讨论、私密工单 | 论坛仅成员；工单仅提交者与管理员 |
| 管理员 | 审核、账户和信用治理、渠道治理、账本核对、仲裁与设置 | 管理权限不等于可获取成员平台 Key 明文 |

成员使用、共享、交易是同一个账户的能力，不要求申请卖家身份或切换互斥角色。管理员也能使用成员功能，并能明确返回成员空间。

以下优先级是原型的交互设计依据，不是已采集的频率统计：接入与查状态应直接；查询和定位问题应保留上下文；贡献、检测和高级配置较复杂，应逐步展开；资金放行、调账、删除和仲裁应降低误操作。

## 3. 必须保留的业务语义

1. **积分不是人民币余额**：约等于人民币只作参考，不承诺兑付。平台账本为零和；人民币仅由 C2C 双方站外支付。没有在线充值、提现或人民币托管。
2. **允许负余额**：信用额度支持透支；常规准入检查要求余额大于负信用额度。余额、信用额度、可用额度（余额 + 信用额度）分开表达。只能出售正余额，不能出售信用额度。
3. **按调用事实结算**：没有预扣、冻结或独立 Key 钱包。所有 Key 共用账号余额，每把 Key 单独统计预算和花费。失败或成功但读不到用量时不收费；界面区分成功、交付、计量与计费结果。价格在调用开始时固定，旧账单不随新报价重算。
4. **目录与渠道不同**：供应商 → 分组 → 分组模型报价；渠道 = 成员选择生效分组 + 自己的上游 Key。模型目录按精确模型 ID 聚合，模型 ID 始终是主名称。分组显示名只辅助说明报价。
5. **价格与证据属于具体候选**：筛选条件必须由同一分组模型 / 渠道同时满足，不拼接不同报价的能力。空价格是未知，明确填 0 才免费；不同计量单位没有可靠换算时不可强排。在线渠道数量不保证瞬时健康。
6. **继承与覆盖清晰**：账号配置模型调用方式；Key 可按模型整份覆盖，未覆盖的模型继承账号。渠道高级配置继承分组与平台；空值继承、明确清空和填写 0 不混为一谈。
7. **先审核后生效**：供应商、分组、模型报价由成员贡献、检测和管理员审核发布。草稿和待审不进入生效目录。完整负向报告允许提交审核；中断、未执行、缺套件不算全测完成。
8. **事实未知就写未知**：未测量、样本不足、未观测、不支持、证据失效、请求失败和实际值为 0 分开。声明的上下文长度不冒充实测长度，典型费用不冒充最终账单。
9. **权限随对象走**：成员可见市场详情不暴露上游地址、凭据、请求头、内部事件、渠道收入或消费者隐私。渠道主看受限调用信息。本人和管理员能看私有调用诊断；平台 Key 明文仅所有者按需读取。
10. **不做站内 AI 聊天产品**：推理、图片与会话通过平台 API 在外部客户端使用。原型要提供对应接入说明和观测，不自行添加聊天工作台、图片画廊、会话内容管理或正文回放。

## 4. 成员功能目录

以下 ID 用于追踪覆盖。每项均须能从新设计的可见入口进入，不能仅存在于某张未连接的画板中。

### F01 身份与账户

- 公开产品介绍与登录；不提供自助注册。实例未初始化时创建首个管理员，已初始化后不再提供初始化操作。
- 管理员创建账户后，成员使用初始密码登录，首次必须改密才能进入业务。重置密码后也需改密。
- 密码 8–128 字符，至少一个大写字母、一个小写字母、一个数字；改密验证当前密码，不复用旧密码。忘记密码联系管理员，不虚构邮件 / 短信找回。
- 查看用户名与角色，修改显示名和密码、退出登录。用户名不可修改。会话失效后重新登录，不能误报保存成功。
- 测试实例展示数据可能清空的提示；固定测试管理员的凭据、启用状态与管理员身份受保护，正常实例不套用这些限制。

### F02 个人概况与待处理

- 余额、可透支 / 可用额度、30 天余额走势；今日调用花费、调用数、渠道收入、在线 / 总渠道数；最近调用。
- 对已有待处理 C2C 交易提供直接入口，能进入相应交易。接入信息仍可直接到达。
- 不要求把全部指标放在首页，也不增加后端不存在的通知中心、已读状态或个性化推荐。

### F03 接入与复制

- 展示和复制平台接口地址、默认 API Key；Key 默认遮蔽，可按需显示或复制完整值，可再次读取，不是仅创建时可见。
- 不同原生协议使用正确入口：OpenAI Chat / Responses、Anthropic Messages、Gemini、图片与 Codex。不能暗示任意客户端都只填同一个 `/v1` 地址。
- 从具体模型到对应调用方式和接入信息。保留 Codex 接入指引：消费者使用自己的平台 Key；客户端可能显示 ChatGPT 认证、未知套餐 `aihub`，不代表 OpenAI 账号或 Pro 权益。官方订阅目前仅为供应商分类。
- 复制成功、剪贴板失败和读取失败有紧邻反馈；无 Key 时进入创建。原型只用明确标记的虚构凭据。

### F04 API Key 管理

- 默认 Key 自动生成；每人最多 20 把。列表看名称、前缀、启用状态、花费和预算进度；创建、重命名、启停、删除、显示和复制自己的 Key。
- 高级设置：全部 / 指定可用模型、每日 / 每月 / 总额预算、过期时间、客户端模型别名 → 平台模型、逐模型独立调用方式。
- 模型多选可检索、查看已选；旧目录退役后可保留历史限制 ID 与既有别名，新选择来自当前批准目录。保留旧 ID 不意味着该模型仍可调用。
- Codex 笔记与历史工具声明默认关闭；开启后会话绑定原渠道与凭据，更改声明不迁移历史，提示改用新会话。
- 预算用尽、过期、停用、达到 Key 数量上限分别显示；删除前说明使用该 Key 的客户端将不能再发起调用。

### F05 模型发现与筛选

- 按精确 ID 聚合模型；搜索 ID，筛选文本 / 图片类型、协议入口、模态与能力、工具、结构化输出、最低实测上下文 / 输出长度、供应商、分组、是否有在线渠道；按 ID 或典型费用排序与分页。
- 显示生效筛选、结果数、清空筛选、无匹配与目录为空。进入详情后返回时保留筛选和位置。
- 实测能力与声明分开；同一候选满足所有条件后才参与聚合。图片价格与 token 价格的单位始终可见。

### F06 模型详情、报价与成本理解

- 模型 ID、各分组报价、可用协议 / 能力 / 渠道、折扣，链接供应商、分组、渠道与批准报告；保留进入时的筛选语境。
- 展示通用输入 / 输出 / 缓存价格，以及存在的模态细分、缓存写入、实际条件档、图片 / 按次 / 调用内工具价格；币种、分母和版本清楚。可折叠复杂价表，不得变成无法查看。
- 典型费用与原厂参考倍率：相同工作负载下的比较单位、样本来源、窗口、样本量、更新时间、报价版本；手续费单列。无参考、无样本或不可比较时说明原因。本人渠道自用净支付为零不代表其上游报价免费。
- 与实际账单链接理解差异，不制造“最低价永远保证”“完整厂商账单一致”等承诺。

### F07 模型调用方式

- 五种方式：便宜优先、稳定优先、延迟优先、速率优先、手动排序；默认便宜优先。可排除渠道、调整手动顺序和相关高级参数。
- 账号模型配置与 Key 对该模型的覆盖能互相定位，显示当前生效来源；恢复继承有明确操作。高级参数包含最多尝试渠道数、首字 / 空闲 / 请求超时。
- 候选展示可比费用、稳定性 / 延迟 / 速率等已有证据，以及不可选、排除、冷却或样本不足的原因；不同指标含义不混淆。
- 手动模式的新渠道默认不选；拖动排序必须有按钮或键盘替代。保存、未保存、冲突和失败可区分。

### F08 供应商与分组

- 搜索供应商，按官方 API、官方订阅、中转站分类浏览；查看名称、图标、简介、Markdown 介绍、官网 / 文档与图标来源。
- 供应商详情有生效分组、按 ID 聚合模型和聚合质量统计；分组详情有介绍、服务状态链接、模型报价及批准报告。
- 模型、供应商、分组、渠道之间可互相到达；资料为空、停用、删除或无权限时给合理返回路径。

### F09 渠道市场

- 浏览成员可见渠道，搜索渠道、按精确模型 ID 筛选与分页；看名称、简介、供应商 / 分组、模型和折扣，进入详情与质量统计。
- 能从市场进入共享自己的渠道。市场视图与自己渠道的经营视图区分，不能把私有经营数据带入他人浏览视图。

### F10 公开质量与批准报告

- 渠道 / 供应商聚合质量：最长 90 天、前期对比、趋势、成功率、首响应、耗时、输出速度、帧间隔、缓存读取占比 / 请求命中率，按模型、渠道、协议、响应方式、尝试结果、状态码拆分与下钻。
- 样本量、未知值和指标口径按需可查；供应商统计合并实际样本，不平均各渠道百分比。无数据不能绘成 0%。
- 批准报告按上游协议、平台代理、官方 CLI 三层呈现：场景结论、原检测项 / 子断言、消耗、版本、容量边界、指纹参考、是否仍有效。
- 区分真实上游证据与合成机制证据；公开报告不含私有任务 / 贡献者身份、上游地址、凭据、请求头、原始错误、配额和原生资源标识。

### F11 资料贡献

- 新增 / 修改 / 停用 / 恢复 / 删除供应商、分组、模型报价。可成套贡献新供应商、首个分组与报价，查看自己的贡献列表与详情。
- 供应商字段：名称、分类、官网、文档、简介、Markdown 介绍、图标获取 / 上传与来源；图标获取失败不阻止保存。
- 分组字段：名称、介绍、状态页、默认设置、地址标签与 URL；可引用同一供应商已批准地址，不复制或修改原地址。
- 模型报价字段：模型 ID、辅助显示名、上游模型名、类型、声明上下文 / 最大输出、报价说明、启用状态；币种、计价单位、通用 / 细分 / 条件 / 单位价；符合条件的官方 API 可作为原厂参考源。
- 编辑与保存草稿，查看字段差异、受影响对象、版本、审核原因与状态；提交审核、撤回等操作遵守状态与权限。新建绑定当前范围的完整报告；紧急停用 / 删除不强制付费检测。
- 草稿、检测中、待补充、可提交、待审、撤回、驳回、批准、版本冲突、发布待完成及可重试状态清楚；后台成功落库但快照未就绪不能显示已完全发布。
- 供应商仍有未删除分组时不能删除；删除分组会业务删除关联渠道，历史账本和在途结算保留。确认中显示受影响范围，不能当作只删一段介绍文字。
- 原型可用结构化表单改善复杂配置录入，必须表达全部现有配置，不自行扩展报价类型。

### F12 私有检测任务与历史

- 从有权限的分组 / 模型及贡献草稿发起全测，填写本次上游 Key。显著提示会真实调用上游，应自行在上游设置消费限额；没有平台累计预算上限，不能画出虚假的总消费封顶。
- 列表与任务详情：排队 / 检测中 / 结束 / 取消 / 中断 / 检测器异常 / 配置已变化；场景覆盖、预计与实际 HTTP、已观测 token、图片、工具、计数 / 查询 / 清理次数。
- 取消检测、恢复未完成项目、选择场景复测；恢复 / 复测重新提供 Key。查看分层场景、独立断言、尝试、容量 / 模态 / 指纹观察、固定版本与参数、待清理资源。
- 查看每轮只读历史报告；复测生成独立报告。不能把“已结束”“全部通过”“可用于创建审核”画成同一状态。

### F13 添加与配置自己的渠道

- 最短创建路径：选择生效分组，填写该分组的上游 Key；其余预选或继承。没有生效分组时到贡献流程。
- 名称、简介、介绍；选择一个或多个入口地址并调整回退顺序。地址属于私有配置；新地址不自动勾选，原已选地址全部移除时停止路由并提示修复。
- 自动执行本 Key 的最小可调用性探测；逐模型看结果、排除与整张报价折扣。可重新探测已保存 Key，探测不覆盖折扣与排除项；没有可调用模型时保留配置并显示原因。
- 更换分组必须提供新分组的 Key。保留原凭据与替换凭据区分；上游 Key 不能从读取接口回显。
- 高级设置仍在同一编辑上下文内折叠，显示已改项数和有效默认来源：User-Agent、整块请求头继承 / 清空 / 覆盖、并发 / RPM、首字 / 空闲 / 请求超时、冷却阈值与时长。

### F14 渠道经营与诊断

- 我的渠道列表、状态与异常；上架 / 自行下架、删除。管理员强制下架时显示原因，成员不能自行绕过。
- 已有渠道首先面向运行状态：收入和质量概览、异常摘要、模型与配置、调用记录、完整分页健康事件均可达；不规定必须有四个标签页。
- 切换这些内容不丢未保存配置，保存入口在长表单中可见；冲突版本不能静默覆盖。删除保留历史调用和账本。
- 调用视图只包含本人渠道允许看到的信息，不包含消费者 IP / 地区、全局候选和消费者账本；公开市场统计与私有诊断分开。

### F15 本人调用、用量与诊断

- 调用列表、汇总与分析；按时间、Key、模型、渠道、标签、协议、流式、结果 / 状态、用量 / 费用 / 耗时等已有条件筛选。按请求 ID 定位，查看原始样本分位、等长前期对比、交叉分析和下钻。
- 实时开关与连接状态；断线、重新连接与数据更新时间有反馈。分析范围过大要求缩小，不静默截断。
- 详情：请求 ID、Key / 模型、实际尝试的上游模型、尝试时间线、回退 / 排除原因、超时、连接复用、各阶段耗时、响应 / 用量 / 计费结果、结束原因、费用组成和关联账单。
- 流式首响应、可靠输出速度与最大帧间隔分开，不称作逐 token 延迟；中断保留已观测部分。没有请求 / 响应正文查看或下载。
- 本人 / 管理员可看客户端近似位置 → 网关出口 → 实际尝试入口的私有地图与链路回放，可暂停、拖动、切速度和尝试。未测量链段标未知，不虚构模型机房或实际用户所在地。
- 原始客户端 IP 与近似地区随私有调用诊断长期保存；定位使用第三方 ipwho.is，提供必要的隐私说明入口，不承诺未采集 IP。

### F16 积分资产

- 积分余额、信用额度、可用额度 / 剩余透支、30 天走势，通往买积分、卖积分、交易与账单。
- 正余额、负余额、接近 / 到达额度边界分开；不要只靠红绿表达。不能把信用额度包装成可提现余额。
- 无预扣的并发调用可能使实际透支超过额度，界面展示实际余额和相应风险，不把信用额度描述成绝不超出的扣费封顶。

### F17 账单、对账与导出

- 时间、类型、说明、关联调用 / 交易、变动、变动后余额、Key；按类型、Key、时间筛选，按天 / Key 汇总，导出 CSV。
- 期间对账：期初、调用支出、渠道收入、C2C 买入 / 卖出、退回、调账、核销、期末。保留正负符号、单位与精度，详情能查看更完整金额。
- 区分报价、估算与已入账费用；缺可靠细分或工具单位时解释未细分 / 未计价原因，不补造费用。

### F18 买积分

- 市场只有卖单，按单价与时间排序；本人卖单不在可买市场中出现。显示卖家显示名、每积分人民币单价、可买量、单笔范围、收款方式名称。
- 填数量，核对数量、单价和应付人民币总额，金额向上取整到分；校验上下限与余量。同买家在同卖单最多一笔未完成交易。
- 创建后才向买家展示完整文字收款方式，进入付款倒计时与交易详情。站外支付，不画平台支付收银台、银行卡绑定或收款二维码。

### F19 卖积分与我的卖单

- 发布：总量、每积分单价、单笔最少 / 最多、最多 5 项文字收款方式（方式名称与账号 / 说明）。省略范围表示不限，必须有足够正余额。
- 发布时积分进入托管。卖单看可买、交易中、已售、已关闭数量与状态；关闭卖单立即退回未占用部分，进行中交易继续。
- 输入错误就地显示；提交前看托管数量和价格，不暗示收取平台 C2C 手续费（当前不收）。

### F20 买卖交易全生命周期

- 我的交易按状态筛选，区分本人买入 / 卖出；详情看对手方、数量、单价、人民币总额、状态、时间线和当前可做的操作。
- 待付款：买家可取消或“我已付款”（可附 500 字以内说明）；卖家实际确认收款后可放行。倒计时以服务端状态为准，超时取消。
- 已付款：等待卖家确认收款并放行，不能再按付款超时自动取消；双方可申诉。
- 放行后托管积分给买家，结果可到对应账单。重复提交不重复结算；交易已被另一端更新时显示最新结果。
- 买家仅在交易未结束时看到完整收款账号；卖家和管理员按权限可见；无关成员不可查看交易。
- “我已付款”仅是买家声明，不能显示为系统已核验到账；“确认收款并放行”明确表示卖家已自行核实站外到账。

### F21 资金申诉

- 已付款后双方可提交 / 更新各自 1000 字以内文字陈述；申诉中积分留在托管，等待管理员判给买家或退回卖家。
- 显示双方陈述、状态和仲裁结果；不是聊天会话，也不提供产品未有的证据图片上传。工单不能替代资金仲裁。

### F22 成员论坛

- 按管理员可配置的板块浏览、分页搜索、发帖、回复；作者可编辑 / 删除本人内容，管理员可管理内容。公告等板块名不是固定导航常量。
- Markdown 工具栏、源码与预览，粘贴 / 上传站内图片、附件上传 / 下载；展示失败、限额、未保存与删除确认。
- 只有登录成员可看；正文图片只使用站内上传文件。删除内容会删除附件。

### F23 私密工单

- 创建、列表、查看、回复与附件；仅提交者与管理员可见，明确“仅你和管理员可见”。
- 待处理、处理中、已解决、已关闭；管理员处理状态，提交者关闭 / 重新打开。关闭后不能新增回复。
- 保留 Markdown 与附件能力；其他成员看不到正文、回复和附件。与论坛讨论、C2C 申诉有清楚区别。

## 5. 管理功能目录

移动端同样需要管理功能，可重新组织成适合触摸的任务流程，不能只缩小桌面表格。

| ID | 能力 | 必须可访问的数据、操作与边界 |

| A05 | 渠道治理 | 全站渠道、所有者、运行概况、模型 / 配置、调用和健康事件；带原因强制下架 / 恢复；跳转按该渠道筛选的管理调用列表；不回显上游 Key |

## 6. 需要贯通的用户旅程

1. 新成员登录 → 首次改密 → 取得平台地址与 Key → 找到可用模型和接入方式 → 在外部客户端调用 → 返回查看调用与账单。
2. 找模型 → 多条件筛选 → 同候选报价 / 证据比较 → 设账号调用方式 → 某把 Key 单独覆盖 → 查看最终生效来源 → 恢复继承。
3. 共享已有分组 → 填上游 Key → 自动探测 → 看模型结果 / 折扣 / 排除 → 上架 → 发现异常 → 下钻调用 / 健康事件 → 修改配置并保存。
4. 没有目标分组 → 成套贡献供应商 / 分组 / 报价 → 全测（含风险提示）→ 完整报告 → 提交审核 → 管理员审差异与证据 → 发布可见 → 创建渠道。
5. 买积分 → 选择卖单 / 数量 → 核对金额 → 创建交易 → 站外付款 → 标记已付款 → 卖家核实并放行 → 积分和账单更新。
6. 卖积分 → 发布卖单 / 托管 → 处理交易 → 确认收款放行；另一路关闭卖单并退回可买部分。
7. 已付款纠纷 → 双方陈述 → 管理员仲裁 → 清楚的资金去向；普通求助另走私密工单。
8. 调用异常 → 保留筛选进入详情 → 查看尝试、回退、计费和链路 → 到对应模型 / Key / 自己渠道配置 → 返回原位置。
9. 管理员待处理 → 指向具体账户 / 贡献 / 渠道 / 申诉 → 处置并确认结果 → 返回待处理上下文；核对到交易、分录与操作记录。

## 7. 通用状态与操作规则

| 情形 | 原型必须表达的结果 |
| --- | --- |
| 首次使用、业务为空、筛选无结果 | 三者区别；一句话说明和当前可行操作，不能全画成同一个“暂无数据” |
| 加载、局部失败、无权限、对象删除 / 停用、404 | 保留可用上下文，给重试或返回；不显示越权对象的私有信息 |
| 表单未保存、校验失败、保存中、已保存、版本冲突 | 字段值保留，错误靠近字段；离开保护，重复提交抑制；冲突不能静默覆盖 |
| 资金操作或治理提交超时 | 显示结果待确认，提供重新查询最新状态；不能仅凭客户端超时判作失败并再次创建交易 |
| 实时连接断开、服务暂不可用 | 连接与最后更新时间明确；重连不冒充新鲜结果 |
| 负余额、预算不足、Key 过期、没有可用候选 | 各有原因与相关入口，不能笼统写成支付失败 |
| 数据未知、采集不完整、旧报告失效 | 不渲染假零值、假百分比、假成功或空洞图表 |
| 删除、放行、调账、仲裁 | 明确对象和影响，按风险确认；普通复制、筛选、展开不加确认 |
| PWA 离线、恢复、更新、外部返回 | 见各端设计要求；这部分是目标原型，不是已实现的离线业务承诺 |

金额展示保留积分 / 人民币单位与正负；人民币到分，积分账本支持九位小数，概览可简化但明细可看完整值。模型 ID、接口地址、Key 前缀与请求 ID 可完整查看和复制，不能因省略号而无法判断对象。

## 8. 设计交付要求

- 先提出适合本端的信息架构和任务分组，简述如何减少寻找和往返；再确定页面 / 面板 / 流程数量，不以当前页面数为目标。
- 提供完整的屏幕目录与连接关系，覆盖成员、管理员、首次使用和错误状态；画出每个实际目的地的主要原型，不能只画首页、列表和通用详情模板。
- 给出一张覆盖表：`功能 ID → 新入口 → 目标屏幕 / 面板 → 主要操作 → 返回位置 → 权限 → 关键状态`。F01–F23、A01–A12 全部有落点；本次新增的 PWA 体验另列为设计目标。
- 复杂功能可以分阶段生成原型，但本次设计的完整目录和覆盖关系不能省略。复用组件无需每屏重画五种按钮状态，业务特有操作与状态必须可查。
- 使用中文和真实业务结构的虚构样本，包含长模型 ID、多报价、负余额、样本不足、渠道不可用、进行中的交易和待审贡献；不使用真实成员、IP、收款账户或密钥。
- 把本规格第 6 节的旅程串起来，逐步说明状态和返回路径；静态画板也需标注交互目标，不让“更多”或“设置”成为未展开的功能黑箱。

## 9. 不增加的产品能力与待确认项

不增加自助注册、组织 / 租户、订阅套餐售卖、人民币充值提现、平台代付、C2C 买单、收款码图片、站内 AI 聊天 / 生图、独立文件 / 向量库 / 容器管理、网关正文保存、推送告警。原生 API 的计数、缓存、图片、会话、后台 Responses 等支持范围供接入与观测使用，不因此生成新的站内内容管理产品。

全局业务搜索、收藏、通知 / 已读体系、跨设备草稿同步、后台自动交易和离线写入均未定义，不可默认为现有能力。桌面命令入口如采用，只导航已有功能与操作；现有列表的局部搜索可以重组。

PWA 安装、独立窗口、断网 / 恢复、应用更新和本地上下文恢复为本次目标原型；是否以及怎样缓存敏感数据、跨设备同步、使用推送、后台同步或新增权限属于待确认的实现决策。原型默认不把凭据、收款资料、IP 或私密正文设计成离线可读。

图表系列 / 图例、论坛引用 / 代码块视觉、统一动效参数和打印样式在现有设计规则中尚待确认。Stitch 可给视觉提案，但应标为提案，不声称是已确认标准。
