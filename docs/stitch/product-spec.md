# Oh-My-AIHub 产品设计简报

请以产品设计师的判断，重新构想一个好用的 Oh-My-AIHub。目标是面向生产使用的产品骨架：让人理解它、找到事情、顺手完成主要任务。细节将在原型确定后补充。

## 产品是什么

Oh-My-AIHub 是一个受邀成员之间共享 AI API、用积分结算、买卖积分的平台。同一个人既可以使用别人共享的 API，也可以共享自己的渠道赚取积分，还可以买卖积分。

几个帮助理解业务的词：

- **模型**：成员想调用的 AI 能力，例如文本推理或图片生成。
- **供应商与分组**：供应商提供 API 服务，供应商下的分组组织不同模型与报价。
- **渠道**：成员把自己在某个供应商分组的 API 接入共享到平台，供其他成员使用。
- **平台 API Key**：成员在外部客户端使用本平台 API 的凭据。共享渠道时填写的是该成员自己的上游凭据。
- **积分**：平台内结算单位。使用 API 支出积分，共享渠道获得积分；信用额度允许余额为负。成员之间买卖积分时，在站外支付人民币。

## 必须保留的核心能力

| 核心能力 | 用户应当能完成什么 |
| --- | --- |
| 身份与账户 | 成员能登录、退出、维护个人资料与密码。账户由管理员创建，成员加入后有清楚的开始使用路径。 |
| 余额与账单 | 成员有容易找到的位置查看积分余额、信用额度、可用额度，以及积分收支记录，理解自己的花费和收入。 |
| 使用 API | 成员能找到模型、了解价格、取得接口地址与自己的平台 API Key，在外部客户端完成接入；能管理自己的 Key，查看基本调用记录与费用。 |
| 共享与经营渠道 | 成员能添加自己的上游接入，维护共享范围与价格，管理渠道的配置和上下架，查看运行状态与收入。 |
| 买卖积分 | 成员能发布卖单、购买积分、查看交易、站外付款、标记已付款；卖家确认到账后放行积分。取消、纠纷申诉与管理员仲裁有清楚的路径。 |
| 在实体中维护公共资料 | 成员在供应商、分组、模型报价等实体的详情中直接发起编辑，提交修改供管理员审核；新增实体从相关目录或父实体中创建。 |
| 必要的管理治理 | 管理员能创建和管理成员、维护信用与积分、审核公共资料、处理渠道上下架与交易纠纷；也能继续使用成员功能。 |

余额和可用额度有清楚的含义，积分与人民币金额各自标明单位。交易进展、操作对象和资金去向容易理解。成员看自己的账户、凭据和交易，管理员按职责处理治理事项。

## 公共资料编辑应当自然发生

贡献融入实体本身的维护过程。用户在查看供应商时就能编辑供应商资料，在查看分组时就能维护分组，在模型的相应报价处就能修改报价。

可以按这个场景自由发挥：

> 我发现某个分组的资料或价格有变化，在对应详情点击“编辑资料”，完成修改并提交。审核进展与结果跟着这个对象呈现，我能回到刚才查看的内容。

创建新供应商从供应商目录开始，创建分组从供应商中开始，新增模型报价从所属分组开始。操作名称、编辑形式和审核进展的呈现方式由你设计。

把查看、编辑、提交和结果连成就近的流程。公共资料经审核生效，自己的渠道配置由自己管理。

## 双端目标

桌面端与移动端分别在两个项目中设计。两端可以采用完全不同的页面、导航和任务结构，共享核心业务含义与贴纸品牌，各自把核心任务做顺手。

桌面端面向长时间工作和安装后的桌面应用体验；移动端面向单手使用和安装后的原生手机应用体验。请围绕各端的实际使用情境做取舍。

## 期待的原型

先提出你的产品组织方式和主要页面，再生成能说明核心体验的页面与连续流程。让人看得出如何进入、完成任务和回到原处，核心能力都有自然的落点。

围绕三条主流程选择主要页面：

- **用 API**：登录，找到模型与价格，取得接入信息，查看调用花费。
- **共享 API**：添加自己的接入，维护共享配置，上架渠道，查看状态与收入。
- **买卖积分**：发布或选择卖单，进行交易，确认收款并放行，查看积分变化。

账户与余额贯穿这些流程。涉及公共资料时，从对应实体直接编辑并提交审核；管理操作在相应任务中有清楚的入口。
